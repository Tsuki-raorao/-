# MQ 发布可靠性验收（2026-10-19）

## 本轮交付

- RabbitMQ 发布启用 correlated confirm、publisher returns 和 mandatory；等待最多 5 秒确认，NACK、退回、超时或连接异常均保留重试。
- 消息使用持久模式，稳定 eventId/messageId 为 `taskId:sequence`。发送成功后数据库标记失败时允许重复发送，下游需按此标识幂等。
- 修复过期 PROCESSING 永久无法恢复的问题；领取时递增 attempts，回写时核验领取代次，防止旧 Worker 覆盖新 Worker 的状态。
- 每次领取一条并立即发送，每轮最多处理 20 条，避免整批等待发送期间租约到期。
- 发布失败按指数退避重试，最大间隔修正为 300 秒，错误记录只保存异常类型。
- 修复既有仓储字段检测对 MySQL/H2 当前 schema 含义不同的兼容性问题；查询限定当前 schema，失败直接暴露，不默默切回旧表结构。

## 真实 Broker 验证

在现有 16G 节点临时创建独立 RabbitMQ 4.1 验证容器，限制内存 384 MiB、CPU 0.5，只映射回环端口，通过 SSH 隧道连接。使用临时专用凭据及随机交换机/队列，无生产业务任务投递，凭据不进入仓库。

已验证：

1. Publisher 等待真实 Broker ACK，队列可接收 JSON 持久消息及稳定事件标识。
2. 未绑定 routing key 产生退回，Publisher 抛错，不当作发送成功。
3. H2 测试 Outbox → Worker → 服务器 RabbitMQ → 测试接收端完整往返，Outbox 成功更新为 PUBLISHED。
4. 恢复、事务回滚、失败退避、旧 Worker 回写保护和并发领取由独立回归测试验证。

测试指令（环境变量只在本机个人配置注入）：

```powershell
# ARGUS_TEST_RABBIT_PORT：仅本机 Broker 或 SSH 隧道端口
# ARGUS_TEST_RABBIT_USER / ARGUS_TEST_RABBIT_PASSWORD：临时测试身份
mvn -f backend/pom.xml -Dtest=TaskEventOutboxTest,RabbitPublisherIntegrationTest,SchemaColumnsTest test
```

未提供 Broker 测试环境时，真实 Broker 用例明确跳过，不报告为实际通过。

本轮全量回归：89 项中 83 项通过、6 项 MySQL 环境专项跳过，0 失败、0 错误。随后新增并发/schema 回归并重跑专项：7 项全部通过，其中含真实服务器 Broker 用例；该专项与全量存在重叠，不累加为总测试数量。

## 边界与下一步

本轮验证的是持久事件发布，不是 RabbitMQ 消费业务闭环上线。现有任务执行仍使用 MySQL 队列和 Agent HTTP；未切换生产 MQ 开关、未部署新的控制中心包。

后续需实现具体消费者的持久幂等、手动 ACK/重试与死信处理、积压监控；还需验证 MySQL Outbox 与 RabbitMQ 的组合故障、Broker 重启和持续负载。当前事件可能重复或乱序，消费者必须回查 MySQL 权威状态，不能按收到消息的先后直接覆盖状态。

测试容器在验证后停止保留，SSH 隧道关闭；不作为常驻生产 MQ 服务。
