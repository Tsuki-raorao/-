# 未序 Argus 部署与备份方案

本方案只描述通用角色与发布方法。真实地址、服务器清单、凭据、业务数据与备份位置由私有部署记录管理，不随源码公开。

## 部署角色

- **控制中心节点**：Nginx、前端静态文件、Java 控制中心；需要管理自身时可另装 Agent。
- **被管节点**：Agent 与业务容器。每个需采集本机状态的节点运行一个 Agent。
- **数据库节点**：MySQL，保存控制中心业务数据，可按资源与隔离要求独立部署。

角色不要求固定云厂商或主机规格。部署前评估 CPU、内存、磁盘、日志增长与备份容量；监控平台等后续组件应单独评估，不能凭设计文档假定已经部署。

## 网络与配置

| 通路 | 配置原则 |
|---|---|
| 浏览器 → Nginx | 保留实际 IP 入口；新建独立预览示例为 9090，已有 80 站点按现状更新；443 与其他服务的路由另行核对 |
| Nginx → 控制中心 | 当前公共模板仅同机回环，示例端口 9091；使用受控内网须重新设计可信代理边界 |
| 控制中心 → Agent | 仅必要来源可达，使用令牌与目标白名单；Agent 默认端口 8090 |
| 控制中心 → MySQL | 内网或受限访问，不直接向公众开放；默认端口 3306 |
| 管理通路 | 与应用访问分离，凭据不进入仓库 |

Nginx 模板为 `deploy/nginx/argus.conf.example`，与 `argus.conf` 内容一致，只安装一份。示例地址和路径不是现场配置。前端以根路径 `/` 与同源 `/api` 提供访问，不能直接挂到子路径；静态目录只放 `dist` 内容。服务环境模板在 `deploy/systemd/`；秘密只注入实际运行配置。完整的配置解释和逐项证据要求见[只读发布清单](../deploy/README.md)。

保留 IP 预览时同样需要匹配浏览器实际 origin（协议、地址和端口）。`ARGUS_CORS_ORIGINS` 使用精确入口，例如 `http://192.0.2.10:9090` 仅为 TEST-NET 示例；代理 Host 与转发协议应与该入口一致，非标准端口不能无意丢失。不要把 CORS 拒绝误判为操作令牌失效，也不要以通配所有来源绕过。

只读发布保持 `ARGUS_API_AUTH_REQUIRED=true`、`ARGUS_API_READ_ONLY=true`、`ARGUS_TASK_CONTROL_ENABLED=false`、`ARGUS_TASK_ALLOW_DOCKER=false`、`ARGUS_AGENT_GATEWAY_ALLOW_CONTROL=false` 以及 Agent `control.enabled=false`。访问令牌必须私下注入，操作令牌留空；HTTP 预览不加密令牌，不能当作真实执行的安全验收。API 令牌是基础访问保护，不能代替完整登录、RBAC 和审计。真实模式的只读 Docker 采集仍需要容器访问权限，也需要按实际操作系统评估权限范围。

中央模板实际绑定回环并启用框架转发处理，因此前置 Nginx 必须清洗和重建信任头，不能把 9091 向公网开放。Agent 的监听地址与公布地址分别配置：同机模板默认回环，跨机读取必须显式选择受控网卡并限制来源。已有 Agent 的稳定节点 ID 和 Inbox/storeId 必须保留，不能因复制新模板改成空目录。

## 发布流程

1. 先盘点现有服务、路径、端口与可用空间；固定版本，在本地运行后端测试、前端构建和 Agent 编译，记录构建校验值。生产服务器使用产物，不运行开发安装脚本。
2. 在私有位置备份数据库、当前应用产物、运行配置和 Agent Inbox，确认剩余空间和恢复方法。
3. 先在隔离环境验证 Flyway 迁移；正式部署关闭演示数据。
4. 检查 Nginx 与 systemd 配置后安排切换，部署后端和前端，验证健康接口、只读保护、授权行为及静态资源缓存。
5. 部署 Agent，保持控制关闭，逐节点验证健康、目标白名单、快照来源和按需日志；MOCK 通过不能代表真实 Docker 已验证。
6. 保留已有 IP 访问及前一版本产物，验证其他服务入口无变化。域名备案通过后的 HTTPS 配置另行评审，不能直接将共享的 443 或全部 HTTP 流量转给 Argus。

项目发布与业务容器维护是不同操作。更新管理平台不应顺带重启或替换被管业务容器。

## 备份范围

| 对象 | 应备份内容 | 恢复验证 |
|---|---|---|
| 控制中心 | 对应版本产物、依赖配置、数据库迁移版本 | 在隔离环境启动并检查健康与数据 |
| 数据库 | 逻辑备份或数据库方案要求的快照、版本与校验值 | 在独立库恢复并检查表、约束和业务读取 |
| Agent | 配置、对应版本产物和独占 Inbox（含 store.id 与任务记录） | 隔离验证持久任务与身份；不能回滚旧目录后直接重启投递 |
| 前端 | 与后端匹配的静态产物、代理配置 | 页面加载与 API 兼容验证 |
| 业务实例 | 容器配置、镜像版本、挂载数据及业务专用配置 | 在独立目录和实例中验证，避免覆盖原数据 |

Minecraft 等有活动写入的业务需要应用一致性备份或维护窗口。仅打包活动世界目录可能产生不一致，压缩包校验通过也不能证明能够恢复。

## 回滚与公开边界

应用回滚使用与数据库结构兼容的前一版本；不要手工修改 Flyway 历史伪造回滚。数据库恢复只能在确认影响、恢复点与目标位置后实施。实例变更失败时恢复经过验证的配置和数据，未知目录不得作为自动清理对象。

可靠任务新增 V5 数据库队列/互斥/事件，旧任务保留为 LEGACY_MOCK 且不下发。Agent Inbox 独立于中央数据库；恢复旧备份可能丢掉之后的命令却保留原 storeId，因此必须先关闭控制、核对未决任务并安排恢复身份，不能按“查询不到”直接重放。UNKNOWN 人工核对/解除互斥接口尚未实现。当前本地进程崩溃验证不等于断电、磁盘回滚或生产业务恢复验收。

源码归档不能替代数据库或业务数据备份。备份、现场检查、日志、截图和真实环境配置可能包含敏感数据，只保存在私有位置；公开仓库仅保留模板、通用流程和脱敏验证结论。
