# 未序 Argus 部署与备份方案

本方案只描述通用角色与发布方法。真实地址、服务器清单、凭据、业务数据与备份位置由私有部署记录管理，不随源码公开。

## 部署角色

- **控制中心节点**：Nginx、前端静态文件、Java 控制中心；需要管理自身时可另装 Agent。
- **被管节点**：Agent 与业务容器。每个需采集本机状态的节点运行一个 Agent。
- **数据库节点**：MySQL，保存控制中心业务数据，可按资源与隔离要求独立部署。

角色不要求固定云厂商或主机规格。部署前评估 CPU、内存、磁盘、日志增长与备份容量；监控平台等后续组件应单独评估，不能凭设计文档假定已经部署。

## 网络与配置

| 通路 | 配置原则 |
|---|---|
| 浏览器 → Nginx | 面向用户的网站入口，由部署环境配置 HTTP/HTTPS |
| Nginx → 控制中心 | 同机回环或受控内网；模板示例端口 9091 |
| 控制中心 → Agent | 仅必要来源可达，使用令牌与目标白名单；Agent 默认端口 8090 |
| 控制中心 → MySQL | 内网或受限访问，不直接向公众开放；默认端口 3306 |
| 管理通路 | 与应用访问分离，凭据不进入仓库 |

Nginx 模板为 `deploy/nginx/argus.conf.example`。其中示例域名不是项目公开入口，需要部署者替换并配置适用的证书。服务环境模板在 `deploy/systemd/`；秘密只注入实际运行配置。

当前版本保持 `ARGUS_API_READ_ONLY=true`、Agent `control.enabled=false`。API 令牌是基础访问保护，不能代替完整登录、RBAC 和审计。真实模式的只读 Docker 采集需要容器访问权限，也需要按实际操作系统评估权限范围。

## 发布流程

1. 固定版本，运行后端测试、前端构建和 Agent 编译，记录构建校验值。
2. 在私有位置备份数据库、当前应用产物和运行配置，确认剩余空间和恢复方法。
3. 先在隔离环境验证 Flyway 迁移；正式部署关闭演示数据。
4. 部署后端和前端，验证健康接口、只读保护与授权行为。
5. 部署 Agent，先以 mock 或只读方式验证健康、目标白名单和快照同步。
6. 验证代理配置与 HTTPS 后再切换用户流量，观察异常并保留可回滚版本。

项目发布与业务容器维护是不同操作。更新管理平台不应顺带重启或替换被管业务容器。

## 备份范围

| 对象 | 应备份内容 | 恢复验证 |
|---|---|---|
| 控制中心 | 对应版本产物、依赖配置、数据库迁移版本 | 在隔离环境启动并检查健康与数据 |
| 数据库 | 逻辑备份或数据库方案要求的快照、版本与校验值 | 在独立库恢复并检查表、约束和业务读取 |
| Agent | 配置、对应版本产物和本地任务持久化设计所需数据 | 当前任务仍在内存，重启恢复能力尚未实现 |
| 前端 | 与后端匹配的静态产物、代理配置 | 页面加载与 API 兼容验证 |
| 业务实例 | 容器配置、镜像版本、挂载数据及业务专用配置 | 在独立目录和实例中验证，避免覆盖原数据 |

Minecraft 等有活动写入的业务需要应用一致性备份或维护窗口。仅打包活动世界目录可能产生不一致，压缩包校验通过也不能证明能够恢复。

## 回滚与公开边界

应用回滚使用与数据库结构兼容的前一版本；不要手工修改 Flyway 历史伪造回滚。数据库恢复只能在确认影响、恢复点与目标位置后实施。实例变更失败时恢复经过验证的配置和数据，未知目录不得作为自动清理对象。

源码归档不能替代数据库或业务数据备份。备份、现场检查、日志、截图和真实环境配置可能包含敏感数据，只保存在私有位置；公开仓库仅保留模板、通用流程和脱敏验证结论。
