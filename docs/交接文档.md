# 未序 Argus 交接文档

更新日期：2026-10-08。先阅读本文和 [开发进度](开发进度.md)，再查看设计文档。此交接面向源码维护，不包含真实环境访问权限或运维资产清单。

## 交付范围

当前交付为基础只读 MVP：Vue 管理台、Spring Boot 控制中心、H2/MySQL 持久化、Java Agent 与只读状态/资源采集。Logo 和“未序娘”头像已接入界面，AI 功能未接入。

用户、Codex 与 Dot 的独立沟通入口见 [协作中转站使用说明](../relay/README.md)；接入状态与维护模板统一在该说明中查看。

特别注意以下事实：

- 控制中心任务接口只更新数据库状态，未向 Agent 执行器下发任务。
- 网页日志页查询 `logs` 表，不是实时 Docker 日志。
- Agent 任务为内存数据，不能跨进程重启恢复。
- 控制中心默认以 60 秒固定延迟拉取快照，Agent 没有主动注册/定时心跳闭环。
- 跨节点同名实例可能互相覆盖，应先迁移实例唯一标识。
- 玩家数未真实采集；TPS 缺失时前端默认 20，不能据此判断业务健康。
- Redis、消息队列、完整 RBAC/审计、监控平台、高并发验证和 AI/RAG 尚未完成。

## 先把本地环境跑通

准备 JDK 17、Maven 3.9+、Node.js 与 npm，从仓库根目录分别启动三个终端。本次验证使用 Node.js 22.23.1 和 npm 10.9.8：

```powershell
.\scripts\start-backend.ps1
```

```powershell
.\scripts\start-agent.ps1
```

```powershell
.\scripts\start-frontend.ps1
```

默认入口为前端 `http://localhost:5173`、控制中心 `http://localhost:8080`、Agent `http://localhost:8090`。控制中心使用 H2，Agent 使用 mock；两者独立启动时，网关仍默认关闭。

H2 的 `./data/argus` 相对于后端工作目录。不要随意改变工作目录后据此判断数据丢失。前端仅开发模式允许演示回退，因此页面能打开不等于后端或 Agent 已接通。

## 配置入口

| 用途 | 文件或变量 |
|---|---|
| 本地后端与 H2 | `backend/src/main/resources/application.yml` |
| MySQL profile | `backend/src/main/resources/application-mysql.yml`；`MYSQL_*` 环境变量 |
| 后端只读/API 认证 | `ARGUS_API_READ_ONLY`、`ARGUS_API_AUTH_REQUIRED`、`ARGUS_API_ACCESS_TOKEN` |
| Agent 网关 | `ARGUS_AGENT_GATEWAY_ENABLED`、`ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS`、`ARGUS_AGENT_AUTH_TOKEN` |
| Agent 本地配置 | `agent/config/agent.properties` |
| Agent 部署模板 | `agent/config/agent.properties.example` |
| Nginx | `deploy/nginx/argus.conf.example` |
| 服务与环境模板 | `deploy/systemd/` |

本地与 Git 保持同一份源码，不维护填写真实连接的另一份代码。MySQL 的主机、库名、用户、密码使用必填环境变量占位符，端口默认 `3306`。真实值保存在个人 IDEA 运行配置或仓库外的部署环境中；IDEA 配置不勾选 `Store as project file`，具体步骤见 [数据库接入](数据库接入.md)。

模板中的本地地址和示例域名不是现有部署入口。配置 MySQL 时关闭演示数据；Agent 真实采集与真实操作是不同能力，`executor.mock=false` 并不意味着应该开启 `control.enabled`。

启用网关需要先有节点记录、允许访问的目标主机和匹配令牌。不要为了联调关闭主机白名单或让 Agent 无认证地暴露在公网。API 只读保护会拒绝注册等写请求，应在受控初始化流程中处理节点配置。

## 关键代码导航

| 位置 | 阅读目的 |
|---|---|
| `backend/.../service/AgentSnapshotSyncService.java` | 定时轮询、快照持久化与离线处理 |
| `backend/.../service/AgentGatewayService.java` | 目标白名单、认证、超时与只读调用 |
| `backend/.../service/TaskService.java` | 当前数据库任务流程与尚未接通的执行边界 |
| `backend/.../service/LogService.java` | 数据库日志查询 |

| `backend/src/main/resources/db/migration/` | V1–V3 数据结构 |
| `agent/src/main/java/com/argus/agent/` | Agent HTTP 接口、执行器与采集实现 |

表中 `backend/.../` 指 `backend/src/main/java/com/argus/controlcenter/`，仅为便于阅读的缩写。

## 建议接手顺序

1. 复现本地构建和只读展示，将失败与演示状态区分清楚。
2. 完成实例节点作用域、用户权限、审计与指标不可用状态。
3. 设计持久化任务状态机，打通命令下发、结果回传、幂等与重启恢复。
4. 连接真实日志与业务适配器，补足错误、超时、断网验证。
5. 按需求接入 Redis、消息队列、历史监控与告警，进行压测和恢复演练。
6. 最后实现 AI/RAG，模型建议与执行权限保持可追溯边界。

不要直接将目标架构文档中的组件标为已完成。进度、问题、验收记录应随实现一起更新。
