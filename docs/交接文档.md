## 当前交付

交付分两层：**生产仍为已上线的 V5 只读版本（`ee97480`），双节点 8 个 Docker 实例、80/9090 IP 入口和最近日志已验收；本轮源码新增 V6 UNKNOWN 人工核对，尚未部署，38 项实际跨模块断言已通过。** V6 包含独立核对记录/队列/审计、Agent 持久闭合回执、确认前证据及原键恢复界面。完整 RBAC、MQ 与 AI 未实现，Logo 和未序娘仍为界面形象。

人工核对不启动、停止、重启容器，不覆写原 Task UNKNOWN/原事件，也不改实例观测。202 只表示接受；APPLIED 是已验证回执和中央原锁的条件解除。BLOCKED 由操作人按 GET 返回的原键和完整原正文显式续办；后续新动作必须另行确认、新键和新 commandId。详见 [UNKNOWN 人工核对契约](UNKNOWN任务人工核对设计.md)。本轮 Agent 89 项 Java/3 项 JSON、后端 80 项一次全通过且 0 跳过（6 项真实 MySQL）、前端 50 项/构建和 Edge 13 类通过；实际双 Java Agent、中央 JAR、隔离 MySQL/Edge 联调 38 项通过。页面只完成真实证据和确认准备、0 POST；API 验证丢 ACK 双进程恢复与独立核对语义，不代表真实 Docker 或生产已升级。

10 月 9 日先前 V5 只读发布的模块证据为 Agent 48 项 Java/2 项 JSON、后端 57 项一次全通过，修复版 28 项实际整链路再次通过。10 月 8 日历史基线 Agent 44、后端分批 54、前端 32/Edge 13 类及 28 项断言仍保留。真实 Docker 只操作独立受限测试容器，已验证运行中重启和重复去重，原 4 个业务容器元数据不变；不外推为生产业务操作或恢复通过。发布模板另通过 12 项代理断言与原生 Nginx 语法检查，完整结果与待办见进度页。

正式切换前已停中央写入、重新备份单库，取回核对哈希并在本机隔离恢复升级后才激活。切换后新静态资源、未认证 401、查看令牌 200、队列为空与控制关闭均核对。最终两节点采集协议 1.1，来源 HOST/DOCKER 正确，聊天站点/健康与 ACME 路径、业务容器元数据不变；收尾恢复重启策略而未再次重启服务。下一位接手者先核对实际版本与只读开关，不重跑已完成迁移。

- 中央实例 ID 保持稳定，节点内 ID 使用 `(nodeId, agentInstanceId)`；迁移保留旧任务/日志外键。
- 网页日志经新中央实例接口读取对应 Agent，属于按需或轮询最近行；旧 `/api/logs` 仍读数据库。
- 来源、null/0、尝试与成功时间明确；180 秒过期，本轮完整清单未发现的实例立即标旧。
- 控制中心默认关闭网关；启用后每轮完成等待 60 秒拉取，没有主动心跳闭环。
- Agent 有输出/超时/队列保护和持久 Inbox；中央任务使用固定命令与数据库租约，旧任务标为 LEGACY_MOCK，不自动下发。
- 202 只表示接收；浏览器断网保留原键，Agent RUNNING 崩溃转 UNKNOWN，已接收命令记录丢失不重放。

## 本地启动与复验

准备 JDK 17、Maven 3.9+、Node.js 和 npm，从仓库根目录分别启动三个终端：

```powershell
.\scripts\start-backend.ps1
```

```powershell
.\scripts\start-agent.ps1
```

```powershell
.\scripts\start-frontend.ps1
```

本地端口分别为前端 5173、控制中心 8080、Agent 8090。默认 H2 和 mock，独立启动不等于网关已接通。H2 路径 `./data/argus` 相对后端工作目录；前端不再把 API 故障替换为演示成功，后端演示数据明确标为 MOCK。

```powershell
mvn -f backend/pom.xml test
.\scripts\test-agent.ps1
npm --prefix frontend test
npm --prefix frontend run build
```

模块与跨模块结果统一保存在 [开发进度](开发进度.md)，复验要求见 [验收清单](验收清单.md)。普通后端测试以 H2/mock 为主，MySQL 专项需要显式 `ARGUS_TEST_MYSQL_*` 指向本机一次性空库；没有配置时会跳过。不要复用个人应用数据库运行配置。测试通过不代表线上发布、真实 Docker、高并发或业务恢复已验收。

| 用途 | 入口 |
|---|---|
| 后端/H2 | `backend/src/main/resources/application.yml` |
| MySQL | `application-mysql.yml` 与 `MYSQL_*` 环境变量 |
| API 保护 | `ARGUS_API_READ_ONLY`、`ARGUS_API_AUTH_REQUIRED`、`ARGUS_API_ACCESS_TOKEN` |
| 中央任务控制 | `ARGUS_API_CONTROL_TOKEN`、`ARGUS_TASK_CONTROL_ENABLED`、`ARGUS_TASK_ALLOWED_INSTANCE_IDS`、`ARGUS_TASK_ALLOW_DOCKER` |
| 独立人工核对 | `ARGUS_TASK_REVIEW_ENABLED=false`、`ARGUS_TASK_REVIEW_ALLOWED_INSTANCE_IDS`；Agent `ARGUS_AGENT_REVIEW_ENABLED=false` 与 `ARGUS_AGENT_REVIEW_INSTANCES`；不因任务开关关闭自动禁止独立获权核对，全局只读仍优先 |
| Agent 网关 | `ARGUS_AGENT_GATEWAY_ENABLED`、`ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS`、`ARGUS_AGENT_AUTH_TOKEN` |
| 独立控制通道 | `ARGUS_AGENT_GATEWAY_ALLOW_CONTROL`、`ARGUS_AGENT_CONTROL_TOKEN`；原 GET 网关保持只读 |
| Agent 本地/部署 | `agent/config/agent.properties` / `.example` 与环境变量 |
| Agent 实际监听 | `ARGUS_AGENT_BIND_ADDRESS` / `server.bind-address`；不同于公布地址 |
| Agent 持久记录 | `ARGUS_AGENT_CONTROL_INSTANCES`、`ARGUS_AGENT_TASK_DIR`、`ARGUS_AGENT_TASK_MAX_RECORDS` |
| 部署模板 | `deploy/nginx/argus.conf.example`、`deploy/systemd/` |

本地与 Git 保持同一份占位符源码。MySQL 主机、库名、用户、密码必填，端口默认 3306；真实值留在 IDEA 个人运行配置或仓库外环境，不勾选 `Store as project file`。完整步骤见 [数据库接入](数据库接入.md)。

V4 为 Java 迁移，旧中央 ID/FK 保留，新采集时间为 `TIMESTAMP(6)`。MySQL DDL 隐式提交，失败不能假定自动整批回滚；生产应用前备份并在独立环境验证。已经被旧版本覆盖的历史归属无法凭迁移还原。发布后不重写 V4，即使 Java 迁移默认 checksum 为 null；后续结构变化新增版本。

V5 同为 Java 迁移，扩展 tasks 并新增 task_queue、instance_task_locks、task_events。历史记录保留并标记 LEGACY_MOCK，不生成队列或重新执行。发布后同样不可重写 V5。10 月 9 日真实旧备份暴露的新旧表排序规则/类型兼容已修复，57 项后端检查一次全通过、无跳过，含 5 项 MySQL 专项；实际备份隔离 V3→V5 保留全部旧 ID，已 V5 的库不重跑该迁移。Agent Inbox 必须随稳定节点保存，禁止两进程共享；旧备份覆盖会带来命令丢失/身份回滚风险，必须停用控制并核对，不能靠删除 Inbox 解除 UNKNOWN。

本轮源码新增 V6，而生产仍 V5。V6 新建独立核对、队列、事件三表，不能修改已发布 V5；不会为旧 UNKNOWN 自动产生人工决定。后续部署要另行验证含旧 UNKNOWN/互斥/事件的迁移和备份恢复，不能因为源码有 V6 就宣称生产已升级。

启用网关前先准备节点记录、受控地址白名单和匹配令牌。保持真实动作关闭；API 只读会拦截节点登记等写入，应在受控初始化流程中配置，而非取消网关保护。

## 接手顺序

V5 双节点只读已上线，本轮 V6 人工核对已经通过本机模块与实际整链路验证，未部署。接手时先核对发布版本、迁移版本和两个独立控制开关，保留原部署及备份，再完成 V6 发布准备与完整权限审计；不能直接开放生产业务动作。Agent 网络仍仅向必要控制来源开放。只读上线、独立测试容器与真实业务控制验收分开记录。业务 Adapter、历史监控/告警、Redis/MQ 与容量按需求推进，AI/RAG 最后接入。

发布遵循 [部署与备份方案](部署与备份方案.md)，不顺带重启业务容器。真实账户、地址、密钥、日志、数据库和现场备份通过独立私有渠道交接，不能补进公开文档。
