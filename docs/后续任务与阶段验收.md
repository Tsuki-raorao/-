# 后续任务与阶段验收

更新：2026-10-19。验收单位是可复现的业务闭环，不以文件数量、编译通过或任意百分比代表完成。每阶段分别记录源码、隔离验证、服务器验证和生产启用状态。

## 阶段安排

| 阶段 | 任务 | 验收标准 | 交付证据 |
|---|---|---|---|
| 1 MQ 闭环（进行中） | 发布确认、Outbox 恢复、持久消费者去重、提交后 ACK、有界重试及死信 | 重复消息仅一条收件事实；乱序不覆盖任务；数据库失败不 ACK；坏消息进入死信；真实 Broker 往返 | 自动化报告、消息/收件/死信计数、故障场景记录 |
| 2 操作与恢复 | 独立测试容器启停/重启、网页确认、Agent 回执、UNKNOWN 人工核对 | 请求到结果可追踪；重复提交不重复执行；丢回执先查原任务；原 UNKNOWN 保留；旧回执不解新锁 | 浏览器流程、任务时间线、Inbox、容器前后状态 |
| 3 性能与数据库 | 端到端阶梯压测、稳定负载、慢 SQL 定位、索引优化、Redis 故障降级 | 报告包含环境/数据量/持续时间/实际速率/P95/P99/错误率/资源；优化有执行计划和前后对比 | 原始结果、压测脚本、EXPLAIN、优化记录 |
| 4 监控告警 | 节点离线/过期、CPU/内存、任务失败、Outbox/死信积压，告警去重与恢复 | 受控触发可见告警；恢复闭合；重复采样不刷屏；未知数据不假装正常 | 规则、触发/恢复记录、监控图和查询 |
| 5 AI 集成 | 对齐另一个会话接口，真实日志和任务证据、RAG、对话持久化、人工批准操作 | 回答引用来源和采集时间；无证据明确未知；无授权不执行；批准后走原任务系统 | 固定问题集、引用核对、权限/注入/超时测试、操作审计 |
| 6 用户体系 | 在 AI 和业务完成后接入登录、注册/邀请、项目成员、权限和凭据管理 | 测试账号迁移；跨项目访问拒绝；撤权生效；最后管理员保护；密钥不外泄 | 权限矩阵、接口/浏览器验收、迁移回滚 |
| 7 发布交接 | 全量回归、配置/数据备份、回滚演练、部署说明及面试材料 | 新环境可按文档复现；真实恢复/回滚成功；演示路径可用；资料与源码一致 | 发布清单、哈希、备份恢复记录、交接包 |

## 执行规则

1. 当前只用少量测试访问身份；完整用户体系排在业务和 AI 之后。
2. 每阶段先做可复查结果，再记录验收结论；失败项修复后复验，不以设计方案替代实现。
3. 生产验证使用受控范围，真实游戏容器动作必须有明确目标；常规联调使用独立测试容器。
4. 本地代码保留占位符，真实配置留在私有环境；按当前要求不推送 GitHub。
5. AI 由另一会话开发，本会话负责接口与整体集成验收，不重复改写其模块。
6. 用户修改过的文件独立保留，不纳入其他模块提交。

## 阶段 3 初始目标（待压测验证）

当前实际架构是控制中心顺序拉取 Agent 健康和实例快照，每轮结束等待采集间隔；不是主动心跳上报。压测按节点数、每节点实例数、每轮耗时和数据新鲜度建模，不能只拿 Agent 心跳确认接口 QPS 推导中央容量。

- 查询场景：先以 20 并发、5 分钟验证 P95 ≤500ms、错误率 <0.1%，再阶梯增加负载找瓶颈。
- 采集场景：先测 10/50/100 个模拟节点，分别记录一轮总时间和最旧快照年龄；达不到既定新鲜度即停止扩规模，优先改造有界并发采集。
- 故障场景：Redis 不可用不丢任务事实；MQ 不可用 Outbox 保留；数据库恢复后可继续处理。
- 这些是拟定验收目标，不是已经测出的成绩。既有 16 并发/1000 次 Agent 本机测试仅作为单接口小规模基线。
