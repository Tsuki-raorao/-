# 数据库与迁移

## 资料用途

Argus 的 MySQL 保存可靠业务事实，H2 只用于本地开发和测试，Flyway 负责结构迁移。

## Argus 使用重点

### MySQL

- 可靠保存用户、项目、节点、实例、任务、任务尝试、任务事件、Outbox 和审计。
- 任务查询使用 `status + next_run_at`、`node_id + status` 等复合索引。
- 高量日志正文和高频指标不进入业务表；MySQL 只保存索引、摘要和状态。
- 应用使用专用账号，不使用 root；远程连接必须通过私网或安全组白名单。
- 需要验证备份恢复、慢查询、连接池和磁盘增长，而不是只验证 SQL 能执行。

### Flyway

- 迁移文件放在 `backend/src/main/resources/db/migration`。
- 迁移文件只追加，不修改已经执行过的版本。
- 每次迁移在测试库和生产副本上先验证，生产发布保留回滚或前向修复方案。
- `flyway_schema_history` 是迁移执行记录，不等同于业务审计。

### H2

H2 文件库用于本地启动和测试，测试配置使用内存库。MySQL 方言差异需要通过 MySQL 集成测试覆盖，不能只凭 H2 测试通过就认为生产 SQL 一定兼容。
