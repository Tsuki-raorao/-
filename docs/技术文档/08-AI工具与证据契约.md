# AI 只读工具与证据契约

更新：2026-10-10。本文是 Argus AI 第一、第二阶段的联调契约。当前线上只读诊断接口已经可用；下列工具分阶段接入，未列为已上线能力。

## 1. 调用边界

AI 请求必须携带当前用户身份和项目范围。控制中心先完成资源权限过滤，再向模型提供工具结果。模型不能直接访问数据库、Docker Socket、SSH、服务器文件系统或任意 URL。

第一、第二阶段只允许 GET 查询和模型回答。模型可以生成 `ActionPlan` 草案，但不能创建任务、修改实例状态、解除 UNKNOWN 互斥或调用任何写接口。

第三阶段已实现一个最小操作闭环：`POST /api/ai/operations/restart`。请求必须包含实例 ID、执行模式、幂等键和 `confirm=true`；服务端固定为 `RESTART`，再复用任务队列、实例互斥、Agent 能力检查和任务审计。未开启任务控制或无操作权限时拒绝执行。该接口不接受自然语言、Shell、Docker 参数或目标地址，AI 只能先给出建议，用户明确确认后才调用。

## 2. 只读工具

| 工具名 | 输入 | 输出 | 数据来源 |
|---|---|---|---|
| `list_nodes` | `projectId` | 节点状态、同步状态、采样时间、数据来源 | `nodes` |
| `list_instances` | `projectId`, 可选 `nodeId` | 实例状态、资源、来源、采样时间 | `instances` |
| `get_instance_logs` | `projectId`, `instanceId`, `limit<=100` | 脱敏日志行、读取时间、实例/节点身份 | Agent 日志读取链路 |
| `list_task_events` | `projectId`, `taskId` | 任务状态和追加事件 | `tasks`, `task_events` |
| `get_recent_changes` | `projectId`, 时间范围 | 配置变更、任务和人工核对摘要 | 审计事实 |
| `search_runbooks` | `projectId`, 查询、版本过滤 | 文档片段、来源、版本、更新时间 | RAG 文档库 |

工具返回必须限制数量、字节数和时间范围。空结果、过期快照、权限不足和 Agent 请求失败要使用不同状态，不能转换成“没有问题”。

## 3. 证据格式

每条证据至少包含：

```json
{
  "evidenceId": "uuid",
  "type": "INSTANCE_SNAPSHOT",
  "source": "central.instances",
  "scope": {"projectId": "project-1", "instanceId": "instance-1"},
  "observedAt": "2026-10-10T00:00:00Z",
  "freshness": "FRESH",
  "contentHash": "sha256:...",
  "summary": "实例状态为 RUNNING，来源为 DOCKER"
}
```

`FRESH`、`STALE`、`PARTIAL`、`UNAVAILABLE` 和 `UNKNOWN` 必须保留。模型只能把 `FRESH` 或明确说明限制的 `PARTIAL` 证据用于结论；不能把文档内容当作实时状态。

## 4. 诊断结果

```json
{
  "diagnosisId": "uuid",
  "status": "COMPLETED",
  "conclusion": "...",
  "confidence": "MEDIUM",
  "evidence": ["evidence-id"],
  "unknowns": ["尚未读取应用日志"],
  "recommendations": ["先读取最近 100 行日志"],
  "actionPlan": {
    "status": "PROPOSAL_ONLY",
    "action": "RESTART",
    "targetInstanceId": "instance-1",
    "preconditions": ["人工确认影响范围"],
    "verification": ["重新采集状态并读取日志"]
  },
  "createdAt": "2026-10-10T00:00:00Z"
}
```

`actionPlan.status` 在 AI 阶段只能是 `PROPOSAL_ONLY`。只有用户明确确认、权限服务再次核验、任务编排器创建新 commandId 后，才允许进入执行状态。模型回答不能直接改变任务或实例状态。

## 5. RAG 资料规则

首批资料包括项目运行手册、Agent 协议、Minecraft/容器 Adapter 说明、部署回滚手册和已脱敏事故复盘。每个片段保存来源路径、标题、版本、更新时间和哈希。删除或过期的资料不能继续作为有效依据。

实时指标、日志、任务事件不进入静态 RAG；它们必须通过只读工具实时读取。检索结果按项目和用户权限过滤，回答必须带来源，不允许只给相似度最高的无来源文本。

## 6. 错误与预算

一次诊断最多 8 次工具调用、总耗时 30 秒、单工具结果 100 行或 64 KiB。工具失败后最多重试一次；第二次失败必须把失败原因写入 `unknowns`。模型超时、额度不足、空回答和格式错误分别记录，不能伪装成诊断成功。

所有诊断请求记录模型名、耗时、工具调用、证据 ID、结果状态和错误码；不记录 API 密钥。生产启用前必须补充限流、会话权限、脱敏和保留期限。

## 7. 验收条件

- 无查看权限的实例不会出现在工具结果或证据中。
- 过期快照不会被标记为实时。
- 模型不能发起 POST 任务、解除 UNKNOWN 或修改数据库状态。
- 每个结论至少能回溯到一条证据或明确列入 `unknowns`。
- 工具超时、模型失败和额度不足均可观察、可重试且不产生运维副作用。
