# Argus AI Agent 分阶段验收

更新时间：2026-10-23

## 目标

Argus 的 AI 不是聊天入口，而是面向项目范围的运维 Agent：读取授权事实、选择受控工具、形成带证据的诊断、等待人工批准、通过已有任务链执行并复查结果。

模型只负责理解和决策建议。项目权限、工具边界、审批、幂等、任务执行、重试和审计由 Java 服务控制。

## 阶段与验收门槛

### P0：治理基线

- 模型密钥只来自服务器私有环境变量，不进入代码、日志和数据库。
- 请求必须绑定用户和 `projectId`；资源读取先经过 `ProjectAuthorization`。
- 模型失败、超时、空响应、额度不足都有明确错误码。
- 实时状态与模型回答分离，回答必须包含证据引用或未知项。

### P1：项目级诊断 Agent（当前实现）

- `POST /api/ai/agent/sessions` 创建项目范围会话。
- `POST /api/ai/agent/sessions/{sessionId}/runs` 启动一次 Agent 运行。
- 运行持久化为 `ai_agent_runs`，步骤持久化为 `ai_agent_steps`。
- 当前步骤链为 `CONTEXT → ANALYSIS → PROPOSAL`，运行结束为 `WAITING_APPROVAL`。
- 取证只包含当前项目的节点、实例、日志摘要和任务历史。
- 模型不能直接访问数据库、Docker Socket、SSH 或 Shell。

验收：同一数据库迁移可重复启动；无项目权限返回拒绝；每次运行都能读取步骤和证据；模型失败后运行状态为 `FAILED` 而不是伪造成功。

### P2：可恢复审批执行（当前已实现首个闭环）

- 将 `PROPOSAL_ONLY` 方案保存为版本化审批对象。
- 审批时重新校验项目权限、目标快照、实例互斥和 Agent 能力。
- `POST /api/ai/agent/runs/{id}/approve` 会重新校验项目权限、目标和执行模式，审批通过后复用现有任务队列，使用幂等键创建 command。
- 审批和拒绝都会追加到 `ai_agent_steps`，服务重启后可通过运行和步骤接口继续查询状态。
- 运行记录保存生成的 `taskId`；`POST /api/ai/agent/runs/{id}/verify` 会读取任务状态，写入 `VERIFICATION` 步骤并将运行标记为 `COMPLETED`、`EXECUTION_FAILED` 或 `VERIFICATION_PENDING`。
- 任务完成后的实例和日志深度复查仍需在下一小步补齐。

### P3：RAG 与长期记忆（知识库第一步已实现）

- 运行手册、Agent 协议、Adapter 文档和脱敏事故复盘进入版本化知识库。
- 片段带来源、版本、更新时间和哈希；过期资料不可作为有效依据。
- 会话记忆、项目事实和知识文档分层保存，跨项目隔离。

本版本新增 `ai_knowledge_documents` 和 `ai_knowledge_chunks`，提供项目范围的文档写入和关键词检索接口；Agent 取证阶段会把匹配片段作为 `runbooks` 证据传给模型。当前是可解释的关键词检索，向量化、重排序和文档自动导入仍待下一步。

可使用 `scripts/ingest-ai-knowledge.ps1` 导入仓库中的首批技术文档。脚本只接收运行时令牌，不保存或打印令牌；重复导入同一来源会淘汰旧版本。

### P4：企业化评测

- 限流、预算、并发隔离、异步恢复、链路追踪和数据保留策略。
- 建立越权、提示注入、重复执行、模型超时和 Agent 离线评测集。
- 发布必须通过回归测试，指标包括成功率、延迟、工具错误率和实际模型成本。
