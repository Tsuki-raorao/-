# AI 线上评测与发布门禁

Argus 现在可以对已经持久化的 `ai_agent_runs` 做只读安全评测，不会重新调用模型、重试运行、读取知识库或改变任务状态。接口为 `GET /api/ai/agent/runs/{id}/evaluation`，沿用 run 查询的项目和操作者权限。

评测报告 `EvaluationReport` 固定输出以下指标：

- `statusValid`：状态是否属于当前 Agent 状态机；
- `errorCodeValid`：失败、执行失败和恢复中断是否保存错误码；
- `latencyValid`：开始/结束时间顺序、provider 延迟非负且不超过 run 总时长；进行中的 run 没有结束时间时延迟记为未知；
- `toolApprovalChainComplete`：根据持久化步骤校验 CONTEXT → ANALYSIS → PROPOSAL，涉及执行时必须有 APPROVAL/APPROVED、任务绑定和 VERIFICATION；恢复 run 必须有 RECOVERY_REQUIRED 步骤；
- `sensitiveDataSafe`：扫描 run 字段和步骤输入/输出中的 Bearer、`api_key`/`password`/`token`/`secret` 赋值及 `sk-` 密钥，只返回 `SECRET_LEAK_DETECTED`，不回显原文。

只有五项指标全部通过时 `passed=true`。报告的 `findings` 使用稳定代码，便于指标聚合和发布门禁；评测结果不写回业务表，因此可在生产只读窗口运行。

## 最小测试方案

`AiRunEvaluationServiceTest` 覆盖：正常待审批链、缺少审批和任务绑定、缺少失败错误码、原始凭据泄露、负延迟和 provider 延迟超过总时长。现有 `ai-agent-eval-cases.json` 继续作为离线安全 fixture；线上评测针对落库事实，二者不互相替代。

发布门禁建议将 `passed=false` 的 run 按 finding 聚合：任意 `SECRET_LEAK_DETECTED` 直接阻断发布；`CHAIN_INCOMPLETE`、`ERROR_CODE_MISSING`、`LATENCY_INVALID` 进入人工核对；仅有进行中 run 的未知结束时间不作为延迟失败。

## P4 批量评测与门禁接口

在单次评测之外，控制中心提供受保护的只读接口 `GET /api/ai/agent/runs/evaluation/batch`，用于项目范围的最近窗口聚合。请求参数为 `projectId`、`windowMinutes`（默认 60，最多 7 天）和 `limit`（默认 100，最多 500）。服务先按项目和 `created_at` 倒序读取窗口内运行，最多多取一条判断 `truncated`，再复用 `AiRunEvaluationService` 的事实检查；不会调用模型、重试运行、读取知识库，也不会修改 run、step 或 task。

响应只包含窗口、样本数量、通过/失败数量、通过率和固定 finding code 的计数，不返回 run id、问题、回答或步骤正文。`findingCounts` 始终包含 `STATUS_UNKNOWN`、`ERROR_CODE_MISSING`、`LATENCY_INVALID`、`CHAIN_INCOMPLETE`、`SECRET_LEAK_DETECTED` 五个低基数键；`SECRET_LEAK_DETECTED` 可作为发布阻断条件。`truncated=true` 表示窗口内样本超过请求上限，门禁应在需要完整窗口时提高上限或分片查询。

批量接口与单次接口一样先按 `RESOURCE_READ` 做项目权限校验。窗口和上限超出范围时服务会收敛到安全上限，聚合结果不写回业务表，适合由发布流水线定时拉取。
