# 未序 Argus 实现详解：从业务到代码

这套资料的用途是帮助你读懂项目并准备面试。它不是技术名词清单，而是沿实际请求解释“为什么需要这段代码、它保存什么事实、失败后如何恢复、有什么证据”。

每章都按以下模板补齐：业务问题 → 设计选择 → 文件/类/方法 → 输入输出 → 字段与变量 → 正常时序 → 异常时序 → 事务/并发/权限边界 → 验收证据 → 面试追问。

## 术语先读

- 控制中心：Spring Boot 后端，管理任务、资源目录和业务事实。
- Agent：每台被管理服务器上的 Java 程序，读取主机/Docker 信息并受控执行。
- 快照：最近一次观测，可能已经过期；不等于实时状态。
- 任务：一次用户操作的中央记录，和发送次数不是同一个概念。
- commandId：同一条远程命令的固定编号，重复传输不能更换。
- 幂等：同一个意图重复提交，不产生第二个业务动作。
- Outbox：业务事务同时写入的待发布事件，防止数据库提交后忘记发消息。
- Inbox：Agent 已接收命令及执行结果的持久记录，用于去重和恢复。
- ACK：接收方确认；必须区分 Broker 确认发布和消费者确认处理。
- UNKNOWN：无法证明远端副作用是否发生，不能自动重放当成失败。
- 灰度：先以只读和受控测试范围验证，再扩大使用。

## 如何判断一句话是否可以写进简历

“实现了”对应源码；“测试通过”对应具体用例与原始结果；“已上线”对应当前服务器配置和运行证据；“性能提升”必须有同环境、同数据量的前后对比。四者不能相互替代。
