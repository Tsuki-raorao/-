# 07 配置与变量字典

配置的作用是改变运行环境与启用范围；数据库业务状态不能用配置替代。真实地址、密码和令牌留在 IDEA 运行配置或服务器私有 env 文件，公开文件仅保留占位符。

## 一、配置如何进入 Java

`application.yml` 的 `${环境变量:默认值}` 先解析为 Spring 属性；`@ConfigurationProperties` 绑定一组属性，`@Value` 注入单个属性。构造器拿到配置和依赖后检查组合是否有效。Agent 是独立 Java 程序，由 `AgentConfig` 读取 properties 与支持的环境变量，不是所有 Spring 属性都能直接用于 Agent。

例如 `ARGUS_TASK_COMMAND_TTL=30s` → `argus.tasks.command-ttl` → `TaskControlProperties.commandTtl`（Java Duration）→ 创建任务时计算 `expiresAt`。`30s` 是持续时间，`expiresAt` 是绝对时间，两者不能混用。

## 二、主要配置、默认值和用途

下表列源码默认值。部署覆盖值以当前进程环境为准，不能仅凭 yml 判断生产功能已启用。

| 配置入口 | 默认值 | 含义与调用位置 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 未指定 | mysql profile 才使用 MySQL 配置；默认本地 H2 |
| `MYSQL_HOST/PORT/DATABASE/USER/PASSWORD` | 见 mysql profile | 数据源连接；密码不写入 Git |
| `ARGUS_API_AUTH_REQUIRED` | false | 是否要求测试访问凭据；公网部署应显式配置 |
| `ARGUS_API_ACCESS_TOKEN` | 空 | 只读访问凭据；不能借此直接操作 Docker |
| `ARGUS_API_CONTROL_TOKEN` | 空 | 操作凭据，和读取凭据必须不同 |
| `ARGUS_API_READ_ONLY` | false | 全局写保护；任务控制开关打开也不能越过它 |
| `ARGUS_AGENT_GATEWAY_ENABLED` | false | 开启中央对 Agent 的 HTTP 读取 |
| `ARGUS_AGENT_GATEWAY_READ_ONLY` | true | 只读网关边界，控制另有专门路径 |
| `ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS` | 空 | 允许的目标主机集合；开启网关时要求有效白名单 |
| `ARGUS_AGENT_AUTH_TOKEN` | 空 | 中央访问 Agent 读取接口的凭据 |
| `ARGUS_AGENT_CONTROL_TOKEN` | 空 | 中央向 Agent 投递命令的独立凭据 |
| `ARGUS_AGENT_GATEWAY_CONNECT_TIMEOUT` | 3s | 建连预算 |
| `ARGUS_AGENT_GATEWAY_READ_TIMEOUT` | 5s | 单次请求预算；采集超时可能保留旧快照 |
| `ARGUS_AGENT_SYNC_INTERVAL_MS` | 60000 | 一轮采集完成后的等待，单位毫秒；不是严格每分钟完成全部节点 |
| `ARGUS_AGENT_SYNC_CONCURRENCY` | 4 | 节点采集并发，允许 1–16；独立固定线程池，不挤占任务调度线程 |
| `ARGUS_TASK_CONTROL_ENABLED` | false | 中央任务控制总开关 |
| `ARGUS_TASK_ALLOW_DOCKER` | false | 是否允许真实 Docker 模式 |
| `ARGUS_TASK_ALLOWED_INSTANCE_IDS` | 空 | 允许操作的中央实例 ID 集合，不是容器名称 |
| `ARGUS_TASK_LEASE` | 45s | Worker 领取时间；启动检查要求大于三次 HTTP 完整预算 |
| `ARGUS_TASK_RETRY_DELAY` | 3s | 未确认结果任务再次查询的间隔 |
| `ARGUS_TASK_COMMAND_TTL` | 5m | 新命令接收期限 |
| `ARGUS_TASK_CONFIRMATION_GRACE` | 5m | 到期后继续核实的宽限 |
| `ARGUS_TASK_REVIEW_ENABLED` | false | 人工核对独立开关，不自动跟随控制开关 |
| `ARGUS_TASK_REVIEW_ALLOWED_INSTANCE_IDS` | 空 | 允许核对的中央实例集合 |
| `ARGUS_REDIS_ENABLED` | false | 启用提交后热状态副本写入 |
| `ARGUS_REDIS_KEY_PREFIX` | `argus:` | key 命名空间，避免与其他应用冲突 |
| `ARGUS_REDIS_TTL` | 120s | 热状态副本寿命，不是任务历史保留期 |
| `ARGUS_REDIS_CONNECT_TIMEOUT` | 500ms | Redis 建连预算；映射 spring.data.redis.connect-timeout |
| `ARGUS_REDIS_COMMAND_TIMEOUT` | 500ms | Redis 命令等待预算；映射 spring.data.redis.timeout，提交后回调仍可能等待这段时间 |
| `ARGUS_MQ_ENABLED` | false | 启用任务事件发布、消费和拓扑 |
| `ARGUS_MQ_EXCHANGE` | `argus.events` | 发布目标 Exchange |
| `ARGUS_MQ_TASK_EVENTS_ROUTING_KEY` | `task.event` | 绑定匹配的消息类别 |
| `SPRING_RABBITMQ_HOST/PORT/USERNAME/PASSWORD` | Spring 默认及私有覆盖 | Broker 连接；不把管理端口当成 AMQP 端口 |
| `SPRING_RABBITMQ_LISTENER_SIMPLE_AUTO_STARTUP` | true | 是否自动启动消费监听器；自定义工厂需要显式传递该配置；不关闭 Outbox 发布 |
| `ARGUS_MONITORING_ENABLED` | false | 开启评估和历史采样 |
| `ARGUS_MONITORING_STALE_SECONDS` | 180 | 完整同步/原始采样的新鲜度界限，秒 |
| `ARGUS_MONITORING_CPU_THRESHOLD` | 85 | 主机 CPU 百分比阈值 |
| `ARGUS_MONITORING_MEMORY_THRESHOLD` | 90 | 已用/总内存百分比阈值 |
| `ARGUS_MONITORING_INTERVAL_MS` | 30000 | 每轮评估结束后等待，毫秒 |

Java 默认字段中还有监控 `taskWindowSeconds=300`、`outboxAgeSeconds=60`、`queueThreshold=100`、`retentionDays=7`。它们属于 `argus.monitoring.*` 的配置绑定；没有在 yml 写出的专用 `ARGUS_*` 别名不能凭空假定存在。使用 Spring 属性名或标准环境变量绑定时，需要核对实际绑定结果。

## 三、Agent 专用配置

| properties 键 | 表达的事实 | 常见误解 |
|---|---|---|
| `server.bind-address` / `server.port` | Agent 监听地址和端口 | 中央 API 端口与 Agent 端口不是一个服务 |
| `node.id` | Agent 节点身份 | 不必等于中央 nodes 表 ID |
| `auth.token` | Agent 只读鉴权 | 不是 Docker 控制授权 |
| `executor.mock` | 是否模拟执行 | MOCK 成功不能证明真实容器已启动 |
| `executor.timeout-seconds` | 本机命令执行预算 | 不应短于服务正常停止耗时而不知情 |
| `control.enabled` / `control.token` | 本机控制开关与独立凭据 | 中央放行不能绕过本机拒绝 |
| `control.instances` | Agent 允许操作的局部实例 ID | 与中央 allowed-instance-ids 分别匹配 |
| `task.directory` | Inbox 文件目录 | 删除目录会丢去重事实，并改变 storeId |
| `instance.discovery` | 是否发现其他实例 | 验收环境关闭，仅保留测试容器 |
| `review.enabled` / `review.instances` | 本机人工核对能力和范围 | 核对不等于执行动作 |

## 四、常见变量命名读法

- `expected`：提交时的预期目标；不是最新采样事实。
- `current`：当前事务读取或锁住的记录；不自动意味着远端当前状态。
- `claim`：本次领取权，带任务和 owner；不只是一个任务对象。
- `candidate`：候选记录；只有条件 UPDATE 成功才算领取成功。
- `ticket/generation`：异步刷新代次；旧响应不能覆盖新页面或新身份。
- `scope/projectId`：数据权限范围；不能只在前端筛选。
- `sampledAt`：原始观测时间；`checkedAt` 是中央评估时间。
- `null/UNKNOWN`：缺少可确认数据，和数值 0、正常、失败均不同。
- `safeLimit`：经过上下界限制的查询数量；用户传入值不是直接 SQL 文本。
- `receipt`：持久回执；要分清 MQ 消费收件与 Agent 人工核对回执，两者不是同一张表。

## 五、面试时解释一项配置的顺序

先说业务含义，再说默认值和单位，然后说哪个类读取、失败时怎么处理、运行环境是否覆盖。例如：租约不是“超时后重做操作”，而是“到期后允许其他 Worker 接管核实”；接管后仍先查询固定 commandId。
