# 12 生产操作开放与验收

2026-10-19，前四阶段发布后补充开放生产操作。此前生产保持只读，独立环境的动作成功不能替代线上可操作；本次将中央、Agent 和网页操作身份一并配置并验收。

## 具体改了什么，为什么

运行包沿用已经验收的版本，未为开放操作改写任务状态机。新增 `deploy/messaging/enable-operations.py`，通过私有 JSON 注入秘密、独立 systemd EnvironmentFile 覆盖开关，保留原配置；重启失败或能力核验失败自动移除本次覆盖并启动原配置。脚本拒绝覆盖既有操作配置，防止重跑时意外换令牌。

| 配置 | 本次实际值/含义 | 设计理由 |
|---|---|---|
| `ARGUS_API_READ_ONLY` | false | 解除全局写保护，真正允许授权操作 |
| `ARGUS_API_AUTH_REQUIRED` | true | 操作不对匿名开放 |
| `ARGUS_API_CONTROL_TOKEN` | 新生成的独立秘密，不入仓库 | 旧查看令牌继续只读；完整账号体系仍后置 |
| `ARGUS_TASK_CONTROL_ENABLED` / `ARGUS_TASK_ALLOW_DOCKER` | true | 接纳持久任务并允许真实 Docker 模式 |
| `ARGUS_TASK_ALLOWED_INSTANCE_IDS` | 9 个中央实例 ID | 只允许明确的业务/测试目标，不因自动发现而获得控制权 |
| `ARGUS_AGENT_GATEWAY_ALLOW_CONTROL` | true | 中央允许经固定协议访问 Agent 命令 API |
| `ARGUS_AGENT_CONTROL_TOKEN` | 与读取、网页操作令牌不同的秘密 | 网页凭据不直接等于主机控制凭据 |
| `ARGUS_AGENT_CONTROL_ENABLED` / `ARGUS_AGENT_CONTROL_INSTANCES` | 两台 Agent 开启及各自容器名白名单 | 中央授权与目标机授权双重核验 |
| `ARGUS_TASK_REVIEW_ENABLED` / `ARGUS_TASK_REVIEW_ALLOWED_INSTANCE_IDS` | true，同一中央目标清单 | 结果不确定时保留独立核对路径，不重放原动作 |
| `ARGUS_AGENT_REVIEW_ENABLED` / `ARGUS_AGENT_REVIEW_INSTANCES` | true，同一 Agent 目标清单 | 核对也需要主机端授权 |

网关 `read-only=true` 保持：它限定普通读取代理的能力，命令走独立 `AgentCommandGateway` 和独立令牌；不能误认为该字段阻止所有远程操作。

## 开放范围

8 个业务容器：mc01、mc02、mc03、fight202609、code-server、open-terminal、open-webui、open-webui-old-v0.10.2；另允许独立 `argus-acceptance-fixture` 验证。每个目标支持 START/STOP/RESTART，网页确认具体节点、中央 ID 和 Agent 局部 ID 后提交，返回 202 只表示已持久接纳。

正式 Broker、测试 MySQL/MQ/Redis、历史 MOCK 不在目标清单。匿名访问仍拒绝，查看令牌的写请求 403，操作令牌试图停止 Broker 也为 403/TARGET_NOT_ALLOWED；该拒绝发生在命令接纳前，没有对 Broker 执行停止动作。全局只读解除后操作令牌可访问既有授权写接口，不能将当前共享操作身份描述成完整的按用户 RBAC。

## 实际上线证据

`production-operations-check.cjs` 从线上公网入口使用 Edge，点击测试容器 START→RESTART→STOP，三条中央任务全部 SUCCEEDED，事件数分别 4/5/5。网页确认目标、持久接纳、终态、刷新、权限边界及无脚本异常共 18 项通过。测试容器回到停止状态，3 条任务保留在生产记录中，名称和目标明确属于测试，未伪装成游戏动作。

正式 Agent 的 Inbox 对三条 commandId 分别仅有一份匹配记录，动作/目标/终态一致。游戏容器 ID/StartedAt/运行状态基线不变。两台 Agent 升级配置前后 nodeId/storeId 和既有 Inbox 摘要保持，原读取配置未改写。

`final-audit.py <ARGUS_HTTP_HOST> --operations` 明确选择开放模式，22 项通过；旧默认模式仍核验历史只读发布，不应再用旧模式断言当前必须只读。数据库 V12、MQ/监控、原 Redis/AI 开关、原环境文件和两个真实节点保持正常，调度队列与锁无未决项，消息 ready/dead 为 0。

## 如何使用和回退

网站进入控制台，点击“更换令牌”，在“访问令牌”中粘贴本机私有说明中的操作令牌并连接。使用原查看令牌时按钮继续禁用是正确权限行为。操作令牌不放进 URL、不嵌入网页脚本。

回退时先确认没有在途任务，再移除中央的 `zzz-operations-20261019.conf` 并重启，恢复此前只读配置；随后按需要撤销 Agent 的同名覆盖并重启。原配置和 Inbox 保留，不清空任务或回滚数据库。切换前持久任务需按状态处理，不能通过删除锁或换命令 ID 来掩盖未知结果。

生产人工核对路径已开启，完整故障流程此前在独立环境验收；本次没有专门制造生产 UNKNOWN，不把“开关生效”说成“本次生产故障核对演练完成”。完整 AI/账号集成不属于本次开放范围。
