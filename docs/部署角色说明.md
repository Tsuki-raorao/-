# 未序 Argus 部署角色说明

本文件描述角色之间的关系，不是运行中的服务器资产清单。真实机器、端口映射、容器清单、账户、DNS、容量和运维记录均保存在仓库外。

## 角色职责

| 角色 | 职责 | 不承担的职责 |
|---|---|---|
| 控制中心节点 | 对外提供 Web 管理台与 API；持久化业务记录；轮询 Agent 快照 | 当前不向 Agent 下发真实任务，不存储业务容器的世界或应用数据 |
| 被管节点 | 运行 Agent 与业务容器；本机采集状态、资源和日志 | 不承担用户权限、跨节点调度或中央数据库职责 |
| 数据库节点 | 保存节点、实例、任务、日志表及迁移历史 | 不等同于日志平台、时序数据库或业务实例备份库 |

一个角色可以独立部署，也可在开发环境合并到同一台机器。是否需要 Agent 取决于是否管理该主机的本地资源，而不是主机所属云厂商或业务类型。

## 当前数据流

```text
浏览器 → Nginx → 前端静态文件
               → 控制中心 API → H2 / MySQL
                        ↓
                  只读 Agent 网关
                        ↓
                   被管节点 Agent
                        ↓
                主机与 Docker 只读采集
```

控制中心默认关闭 Agent 网关。启用后先配置节点记录、目标白名单和认证令牌，再由控制中心定时读取快照。默认每轮完成后等待 60 秒执行下一轮，不是 Agent 主动定时上报；接口中存在 heartbeat 名称也不代表主动心跳已经实现。

Agent 已有日志读取和受控执行器，但当前网页日志仍读取中央 `logs` 表，网页操作仍只改变中央数据库状态。不能把上述数据流解释为完整远程控制闭环。

## 新节点接入前检查

1. 选择匿名且唯一的节点 ID，并在私有配置中记录网络入口。
2. 安装 Agent，配置有效令牌与受控网络来源，保持远程动作关闭。
3. 用本地或受控通路检查 Agent 健康与实例快照，再录入控制中心节点配置。
4. 配置控制中心的 `ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS` 与 `ARGUS_AGENT_AUTH_TOKEN`，再启用只读网关。
5. 核对采集数据来源和刷新时间。当前实例 ID 尚未按节点隔离，接入同名容器前需先完成数据模型修复。

一般 Docker 容器可使用现有只读发现能力；业务指标需要单独适配器。Minecraft 玩家数、TPS 及其他服务专属指标不能从容器 CPU/内存自动推断。

## 后续角色

Redis、消息队列、指标存储、日志平台、告警与 AI/RAG 在目标架构中有规划，目前没有完成接入。规划部署时应补充资源预算、依赖关系、备份恢复与权限设计，再选择实际节点。
