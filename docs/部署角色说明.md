# 未序 Argus 部署角色说明

更新：2026-10-09。本文是部署角色说明，不是当前线上资产清单。中央已一次激活至 V6，两台 Agent 已更新为包含人工核对协议的版本，控制与核对均关闭。生产 2 节点/8 实例原 ID 保留，新启动后的双节点各 4 个 DOCKER 实例、日志身份及公网接口验收通过；最新浏览器结论及分阶段状态见 [开发进度](开发进度.md)。真实地址、容器清单、凭据和运维记录保存在私有资料中。

| 角色 | 职责 | 当前边界 |
|---|---|---|
| 控制中心节点 | Web/API、快照与日志、持久任务及核对队列、授权、固定命令对账和核对事件审计 | 已发布 V6，控制/核对关闭；完整用户体系、RBAC 与生产核对执行验收未完成 |
| 被管节点 | Agent 与业务容器；本机采集及受控执行，独占 Inbox 保存命令和独立核对回执 | 不承担跨节点调度；RUNNING 崩溃转 UNKNOWN，不自动重放；核对先落盘再条件解锁 |
| 数据库节点 | 节点、实例、任务、队列/互斥/事件、核对意图/回执、日志摘要及迁移历史 | V6 核对表已创建且为空；不代替 Agent Inbox、时序库或业务实例备份 |

角色可独立部署，也可在开发环境合并。是否运行 Agent 取决于是否采集该主机的本地资源，与云厂商或业务类型无关；生产节点清单需按实际环境验证。

## 现有数据流

```text
浏览器 → Nginx → 前端静态文件
               → 控制中心 API → H2 / MySQL 快照与业务记录
                       ↓
                 只读 Agent 网关 → 被管节点 Agent → 主机 / Docker
                 持久任务队列 → 受限命令通道 → Agent Inbox → 执行与状态核对
                 独立核对队列 → 固定核对通道 → Agent CLOSED 回执 → 中央 APPLIED 审计
```

上述核对链路是已实现的代码能力，线上启用状态受中央/Agent 各自开关与迁移版本约束。APPLIED 不把原 UNKNOWN 改成成功，也不执行原动作。

中央网关默认关闭；启用后每轮完成等待 60 秒拉取 health/instances。完整清单校验通过才事务保存；失败保留旧证据。网页每 15 秒读取 API，按来源、采样、同步结果和 180 秒阈值显示新鲜度，没有主动注册/心跳上报闭环。

网页最近日志走 `/api/instances/{centralId}/logs`，由中央解析正确节点和 Agent 局部 ID；按需/轮询读取，不是持续日志流。旧 `/api/logs` 仍读数据库摘要。任务走独立授权通道，202 只代表接受，中央按固定命令核对结果；不把任务成功直接写成实例状态。完整模块测试和实际跨模块/生产验收分开记录，最新见开发进度。

## 接入新节点

1. 准备稳定唯一的节点身份，在私有配置中记录实际入口。
2. 配置 Agent 令牌、必要来源与资源上限，保持远程动作和人工核对关闭。
3. 核对 Agent 1.1 的来源/时间/可空指标；mock 必须明确标为 MOCK。
4. 通过受控初始化准备中央节点记录，配置主机白名单和令牌后启用只读网关。
5. 核对部署版本需要的迁移（当前源码至 V6）、同名实例中央 ID 不同、快照和最近日志属于正确节点；失败与旧快照可辨认。升级之前先完成备份恢复演练。

若将来启用控制，还需独立 API 操作令牌和 Agent 控制令牌、中央实例允许列表、Agent 局部 ID 允许列表、稳定 nodeId/storeId 及明确 MOCK/DOCKER 模式。真实 Docker 有单独开关；发现到一个容器不意味着允许操作。保持默认关闭，先完成隔离真实环境验收，不因本机 mock 通过直接开放。

人工核对使用另一组默认关闭的开关与核对名单，仍要求操作令牌，中央全局只读优先。允许在动作关闭时核对旧任务，但不会间接开放新动作；人工需明确接受不重放与残余副作用风险。更换 store、记录丢失或已知执行资源仍活跃时不强制解锁。

Agent Inbox 是该节点的持久记录，不能跨节点共享目录或随意清空。恢复旧备份前须停止控制并核对未决命令；同名容器重建仍属于当前按名称识别的边界，尚未绑定 Docker 物理 ID。

本次两台 Agent 发布保留原 Inbox、身份、读取令牌和监听范围，各只重启 Agent 一次；业务容器的 ID、启动时间、重启次数和状态不变。没有在生产生成核对回执或释放 UNKNOWN 锁。

V4 保留旧 ID 和任务/日志引用，但不恢复历史已覆盖数据。新增节点需要真实环境只读验收，不能以本机模拟测试代替。一般 Docker 容器可复用发现能力；玩家数、TPS、数据库查询性能等业务专属数据需额外适配器。

Redis/MQ、历史指标存储、日志平台、告警和 AI/RAG 仍为后续规划。部署前须补充容量、权限、网络、备份与恢复设计，不能因设计文档出现组件就认定已经在线。
