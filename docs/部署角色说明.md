# 未序 Argus 部署角色说明

更新：2026-10-08。本文是部署角色说明，不是当前线上资产清单。本轮改动尚未部署，真实地址、容器清单、凭据和运维记录保存在仓库外。

| 角色 | 职责 | 当前边界 |
|---|---|---|
| 控制中心节点 | Web/API、持久化、轮询快照、转发只读日志 | 尚不向 Agent 下发真实执行任务 |
| 被管节点 | Agent 和业务容器；采集本机状态、资源与日志 | 不承担中央用户授权或跨节点调度；任务内存保存 |
| 数据库节点 | 节点、实例、任务、日志摘要与迁移历史 | 不代替时序库、日志检索平台或业务实例备份 |

角色可独立部署，也可在开发环境合并。是否运行 Agent 取决于是否采集该主机的本地资源，与云厂商或业务类型无关；生产节点清单需按实际环境验证。

## 现有数据流

```text
浏览器 → Nginx → 前端静态文件
               → 控制中心 API → H2 / MySQL 快照与业务记录
                       ↓
                 只读 Agent 网关 → 被管节点 Agent → 主机 / Docker
```

中央网关默认关闭；启用后每轮完成等待 60 秒拉取 health/instances。完整清单校验通过才事务保存；失败保留旧证据。网页每 15 秒读取 API，按来源、采样、同步结果和 180 秒阈值显示新鲜度，没有主动注册/心跳上报闭环。

网页最近日志走 `/api/instances/{centralId}/logs`，由中央解析正确的节点和 Agent 局部 ID；按需/轮询读取，不是持续日志流。旧 `/api/logs` 仍查询数据库摘要。网页任务仍只改变中央模拟记录，不能把只读数据流称为完整远程执行链路。

## 接入新节点

1. 准备稳定唯一的节点身份，在私有配置中记录实际入口。
2. 配置 Agent 令牌、必要来源与资源上限，保持远程动作关闭。
3. 核对 Agent 1.1 的来源/时间/可空指标；mock 必须明确标为 MOCK。
4. 通过受控初始化准备中央节点记录，配置主机白名单和令牌后启用只读网关。
5. 核对 V4 已迁移、同名实例中央 ID 不同、快照和最近日志属于正确节点；失败与旧快照可辨认。

V4 保留旧 ID 和任务/日志引用，但不恢复历史已覆盖数据。新增节点需要真实环境只读验收，不能以本机模拟测试代替。一般 Docker 容器可复用发现能力；玩家数、TPS、数据库查询性能等业务专属数据需额外适配器。

Redis/MQ、历史指标存储、日志平台、告警和 AI/RAG 仍为后续规划。部署前须补充容量、权限、网络、备份与恢复设计，不能因设计文档出现组件就认定已经在线。
