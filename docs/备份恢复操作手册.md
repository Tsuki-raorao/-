# Argus 备份恢复操作手册

更新时间：2026-09-30

本手册使用通用示例容器 `minecraft-example` 和世界目录 `example-world`，不是生产环境操作记录。执行前必须替换为已核验的实际参数。本手册不会自动连接服务器，也不会自动停止容器。恢复 Minecraft 前必须先确认维护窗口、玩家已退出、容器已停止写入、目标目录和备份校验值；恢复 MySQL 前必须先确认应用停止写入或处于只读模式。

## 1. Minecraft 世界恢复

1. 在目标游戏节点校验备份（将 `<备份批次>` 替换为实际目录名）：

   ```bash
   cd '/srv/argus-backups/<备份批次>'
   sha256sum -c SHA256SUMS
   ```

2. 先保存当前容器和目录快照，避免覆盖后无法回退：

   ```bash
   docker inspect minecraft-example > /srv/argus-backups/pre-restore-minecraft-example.inspect.json
   mv /srv/minecraft/example-world '/srv/minecraft/example-world.before-restore-<恢复批次>'
   mkdir -p /srv/minecraft
   tar --numeric-owner --xattrs -xzf '/srv/argus-backups/<备份批次>/example-world.tar.gz' -C /srv/minecraft
   ```

3. 核对目录属主、`server.properties`、Mod 和端口映射后，再按原镜像和挂载参数恢复目标容器。不要从文档猜测镜像或参数，必须以保存的容器 inspect 文件为准。

4. 启动后检查 `docker ps`、最近日志、实际游戏端口和玩家连接；验证通过后继续按保留策略保存旧目录，失败则停止新容器并恢复旧目录。

其他实例使用同样流程，把容器名和目录替换为备份中实际名称。重要世界最好安排停服后再打包；脚本在线压缩只能作为应急快照，不能保证游戏写入期间的一致性。

## 2. Argus MySQL 恢复

1. 校验 SQL 压缩包：

   ```bash
   sha256sum -c argus-<时间>.sql.gz.sha256
   gzip -t argus-<时间>.sql.gz
   ```

2. 先在临时数据库或恢复环境导入并检查 Flyway 版本、表数量和关键节点行数：

   ```bash
   gunzip -c argus-<时间>.sql.gz | mysql --host=<数据库地址> --port=3306 --user=<专用账号> -p argus_restore
   ```

3. 确认恢复结果后，再由数据库管理员决定是否切换正式库。不要直接对生产库执行覆盖导入；应用恢复后先访问 `/api/health`，再查看节点和实例状态。

## 3. 验收记录

每次恢复至少记录：备份文件名、SHA256、执行人、开始/结束时间、是否停服、Flyway 版本、节点/实例数量、Minecraft 端口或健康检查结果。密码、私钥、令牌和完整连接串不得写入记录。
