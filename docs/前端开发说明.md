# Argus 前端开发说明

## 1. 作用范围

前端位于 `frontend/`，使用 Vue 3、TypeScript 和 Vite。当前页面面向 Argus 控制中心，包含概览、节点、实例、任务、日志五个入口。页面可以在后端尚未启动时使用内置演示数据预览，但演示数据不代表服务器真实状态。

## 2. 页面路由

前端使用轻量 hash 路由，避免在 Nginx 或静态文件服务器上额外配置 history fallback：

| 地址 | 页面 | 数据来源 |
| --- | --- | --- |
| `/#/overview` | 概览 | 节点、实例、任务、日志 |
| `/#/nodes` | 节点 | `GET /api/nodes` |
| `/#/instances` | 实例 | `GET /api/instances` |
| `/#/tasks` | 任务 | `GET /api/tasks` |
| `/#/logs` | 日志 | `GET /api/logs?instanceId=...&limit=100` |

地址栏变更会同步菜单状态；页面刷新后仍可回到当前页面。

## 3. API 和降级策略

`src/api.ts` 是前端唯一的 API 入口，负责三件事：

1. 给请求补上 `/api` 前缀和 JSON 请求头。
2. 解包控制中心统一响应 `{ code, message, data }`，非零 `code` 视为失败。
3. 开发环境接口不可用时返回 mock 数据，让页面可独立开发。

接口字段以 `docs/API.md` 和后端 VO/domain 类为准。`normalize*` 函数将后端的大写枚举和不同版本字段转换为页面使用的类型；新增后端字段时优先在这里兼容，不要在模板中散落转换逻辑。

## 4. 轮询与操作

页面挂载后加载一次全量数据，之后默认每 15 秒刷新。日志实例切换会立即重新拉取日志；关闭“自动刷新”只暂停定时刷新，不影响手动点击“刷新数据”。实例启动、停止和重启提交后会重新加载实例、任务和日志，避免页面保留旧状态。

当前“添加节点”“创建实例”“导出日志”按钮只显示“后续版本开放”提示，因为对应后端接口和权限流程还未完成。不要在前端直接模拟成功，避免用户误以为服务器已经变更。

## 5. 主要变量对照

| 变量 | 类型 | 中文含义 | 用途 |
| --- | --- | --- | --- |
| `page` | `Page` | 当前页面 | 控制菜单和页面内容，并同步 hash 路由 |
| `nodes` | `NodeItem[]` | 节点列表 | 展示主机、Agent 心跳和资源摘要 |
| `instances` | `Instance[]` | 服务实例列表 | 展示 mc01 等实例并提交启停操作 |
| `tasks` | `Task[]` | 任务记录 | 展示异步任务状态与审计信息 |
| `logs` | `LogLine[]` | 日志行 | 展示选中实例的运行日志 |
| `selectedInstance` | `string` | 当前日志实例 | 拼接日志查询参数 `instanceId` |
| `autoRefresh` | `boolean` | 是否自动刷新 | 控制 15 秒轮询是否执行 |
| `notice` | `string` | 页面提示 | 显示操作提交和暂未开放功能 |

侧边栏完整显示横版 Logo，宽度为 168px、`max-width:100%`、`height:auto`，适配 208px 和 236px 侧栏；下方保留“智能运维控制台”副标题，移除旁边重复的 ARGUS 字标。

未序娘的头像资源位于 `frontend/public/weixu-niang.png`，侧边栏个人资料和右上角用户区域共用该资源，显示名称为“未序娘”，副标题为“AI 运维助手”。该头像目前只承担产品品牌和界面展示作用，AI 对话、诊断、RAG 和自动化决策功能仍未启用。

历史品牌资源可在本地单独留档，不属于公开源码交付内容；回滚应使用经过验证的发布包或对应版本源码重新构建。

品牌资源更新后运行 `npm run build`，检查生成的静态文件和页面显示，再按部署流程发布。生产发布前备份现有静态站点并校验备份；构建文件名、发布包校验值、实际备份路径和发布结果记入受控运维档案，不写入公开仓库。更新品牌资源本身不会启用 AI 功能。

## 7. 本地检查

```bash
cd frontend
npm install
npm run build
npm run dev
```

开发服务器默认在 `http://localhost:5173`，`/api` 代理到 `http://localhost:8080`。生产部署前应把代理或反向代理指向实际控制中心，并通过 HTTPS 保护登录和控制操作。

## 8. 后续拆分计划

当前 `App.vue` 仍保留了 MVP 页面布局，后续可以按以下顺序拆分，避免一次改动影响所有页面：

1. 将实例表、日志终端、节点卡片抽为 `components/` 子组件。
2. 将页面状态抽为 `stores/` 或组合式函数，接入统一权限和错误提示。
3. 接入 WebSocket 事件，只做实时推送；断线后仍通过 REST 补齐事实状态。
4. 接入真实指标、权限和审计后，再删除或单独隔离 mock 数据。
