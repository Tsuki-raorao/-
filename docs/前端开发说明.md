# Argus 前端开发说明

更新：2026-10-09。当前前端已随 V6 只读版本部署。UNKNOWN 证据/确认/恢复交互通过本机验收，但生产控制与核对开关仍关闭，没有提交生产核对；本机功能与线上只读展示分别记证。

## 1. 页面与数据链路

前端位于 `frontend/`，采用 Vue、TypeScript 和 Vite。实际锁定版本为 Vue 3.5.43、TypeScript 5.7.3、Vite 6.4.3；`package.json` 保存允许范围，`package-lock.json` 保存构建使用的具体版本。

| hash 路由 | 页面 | 数据来源 |
|---|---|---|
| `/#/overview` | 概览 | 节点与实例快照；只统计近期验证的真实数据 |
| `/#/nodes` | 节点 | `GET /api/nodes` |
| `/#/instances` | 实例 | `GET /api/instances` |
| `/#/tasks` | 任务与执行结果 | `GET /api/tasks`；所选任务的详情和事件接口 |
| `/#/logs` | Agent 最近日志 | `GET /api/instances/{controlId}/logs?limit=100` |

页面默认每 15 秒重新读取中央 API。日志只在日志页且已选择有效实例时读取；它是一次读取或周期查询，不是 WebSocket 日志流。旧 `/api/logs` 仍是后端数据库日志接口，当前网页不再混用它。

开发和生产均使用严格请求：网络、认证、业务错误不会自动替换成内置演示数据。需要演示时使用后端明确带 `dataSource=MOCK` 的结果；页面显示“模拟数据”，不会计入真实近期节点/实例统计。

## 2. 多节点身份与日志防串线

`Instance.id` 是中央不透明唯一 ID，所有选择、动作和日志请求使用它，不能以容器名或 `agentInstanceId` 替代。实例卡片与日志选项同时显示所属节点、容器标识和中央 ID，同名容器可以区分。没有 ID 的条目不能发起请求。

日志响应结构为：

```text
{ code, message, data: {
  instanceId, nodeId, agentInstanceId, collectedAt, lines: string[]
} }
```

前端核验中央实例 ID、所属节点、容器标识与选择目标一致。切换选择、离开日志页、清除令牌或实例从目录消失时，立即清空旧日志并取消请求；请求序号还会拦截不响应取消的晚到成功或失败结果。未选择时不请求默认 `mc01`。

加载中、读取失败、成功但空日志、筛选后无匹配内容有独立状态。失败不会保留上一实例的日志或用模拟内容冒充成功；日志按文本展示，内容中的 HTML 不会执行。`collectedAt` 表示本次日志读取时间，不是每行日志的生成时间。

## 3. 可信采集与缺失值

`src/models.ts` 统一归一化来源、时间、采集状态和指标；`src/api.ts` 负责认证、统一响应与超时；`src/logs.ts` 负责日志选择和竞态保护。`src/task-control.ts` 负责控制能力、请求标识和待确认意图；`src/task-detail.ts` 负责详情读取与竞态保护。

| 数据 | 关键字段 | 展示原则 |
|---|---|---|
| 节点 | `lastCheckedAt`、`lastSuccessfulSyncAt`、`syncStatus`、`syncErrorCode` | 区分最近尝试和最近成功，失败或部分同步标旧快照 |
| 实例 | `nodeId`、`agentInstanceId`、`lastSeenAt` | 按节点核对实例观测，中央 ID 负责唯一定位 |
| 采样 | `dataSource`、`sampledAt`、`metricsStatus` | 显示来源、采样时间及指标是否完整 |
| 数值 | 可空 CPU、内存、玩家数 | 真正的 0 保留；缺失显示“未采集”或“不可用”，不注入 TPS=20 等默认正常值 |

`HOST`、`DOCKER` 表示采集来源；`MOCK` 明确显示模拟；缺失/不支持的来源按 `LEGACY` 处理，并标记历史数据未验证。旧协议的 `lastHeartbeat` 不用于推断新采集成功。

快照过期阈值在 `SNAPSHOT_MAX_AGE_MS` 中明确设为 **180 秒**。节点离线、同步失败/部分同步、采集时间缺失、没有所属节点或超过阈值，均不能标为当前已验证状态；最近值可保留，但旁边有旧快照或未验证标记。时间比浏览器快超过 60 秒时也标为未验证。每秒更新显示时钟，即使关闭自动刷新，快照仍会按时过期。

完整同步中的 `instance.lastSeenAt` 与 `node.lastSuccessfulSyncAt` 使用相同批次时间。如果实例时间早于节点最新成功批次，立即标记“旧快照 · 本轮未发现”，不等满 180 秒；这覆盖空清单和某容器已从清单消失的情况。比较保留后端微秒精度，历史数据不删除，也不计入近期运行数。页面先读取节点批次再读取实例清单，避免把新节点批次与旧实例响应拼接而误判“本轮未发现”。

概览平均 CPU 只纳入近期验证、来源真实、指标可用或部分可用且 CPU 非空的节点，CPU 为 0 的有效样本也参与计算。没有样本时显示 `—`，不显示虚构的 0%。

## 4. 访问保护与现有功能边界

API 令牌由用户输入，保存在当前浏览器的 `sessionStorage`，请求通过同一个 Bearer 头发送，源码和 URL 不携带令牌。“输入令牌 / 更换令牌”支持查看或操作令牌；角色由服务端判断，浏览器不指定操作人。更换、清除令牌都会使旧页面、日志、任务详情和提交等待失效，避免旧响应把数据重新显示出来。401 显示认证入口；日志错误不会被当作空日志或整个平台正常。

每次请求最长 12 秒。页面轮询间隔为 15 秒；手动刷新会使用新的请求序号，旧读取不能覆盖新结果。日志的自动刷新开关同时控制页面定时刷新，手动刷新仍可用。

只读状态继续由健康接口返回，缺失值按只读处理。页面另读 `GET /api/control/capabilities`，只有 `controlEnabled`、`canControl` 都为真，且全局动作与目标动作允许列表同时包含所选动作、`blockingTaskId=null`，才允许确认新操作。能力接口缺失、失败、未知执行模式、互斥字段无效或重复目标身份均不能打开按钮；它失败不会让已有只读观察页整体不可用。正在刷新、连接不可用或实例身份不完整也禁用操作。

实例互斥以服务端 `targets[].blockingTaskId/blockedReason` 为准，不能用最近 100 条任务或 UNKNOWN 状态推断。即使阻塞任务不在最近列表，也可从实例行打开其详情。只读时仍保留锁的说明和详情入口。已有不确定的原动作请求需要 `targets[].canConfirmPending=true`、原模式及全局授权，而且当前实例仍存在、nodeId/agentInstanceId 与原意图一致、来源与原模式一致，才能显式同键核对；未知来源或已知绑定变化时禁用。被锁不能误拦已接受请求的查询，也不能借此为新操作放行。

这是基础令牌角色和实例授权，不是完整登录与 RBAC。添加节点、创建实例、完整用户审计、历史指标与告警仍未实现。

## 5. 受控任务与不确定结果

前端遵循[可靠任务接口与恢复约定](可靠任务接口与恢复约定.md)。点击启动、停止、重启先显示确认框，明确所属节点、中央实例 ID、Agent 局部 ID 和服务端报告的执行模式。真实 Docker 操作说明服务中断风险，Agent 模拟明确说明不会操作 Docker；取消不产生请求。确认时再核对当前权限、目标与执行模式，变化后需重新确认。

每次明确的新操作使用安全随机 UUID v4 作为 `Idempotency-Key`，正文只发 `action` 和 `expectedExecutionMode`。UUID 用 `crypto.getRandomValues` 构造，可在没有 `crypto.randomUUID` 的 HTTP/IP 预览环境使用；没有安全随机源则拒绝提交，不退回普通随机数。

只有 **HTTP 202** 且返回目标、动作、模式、命令身份匹配的 Task，才显示“控制中心已接收任务”。这不表示执行完成，即便同键重查返回一个已结束任务，也先说明它是排队/查询确认，再在详情显示任务结果。其他 2xx、无效 JSON、错目标或网络异常都不能冒充有效接受。

发送前将不含令牌的原操作意图和幂等键写入当前会话存储。重复点击不重复发送；超时、断线、无效返回后保留“提交结果待确认”，禁止创建新的意图。刷新页面或清除令牌不丢弃原键，重新连接后可点击“用原请求核对”：如果上次已入队会返回原任务，如果上次未入队，本次可能首次排队。页面对此明确提示，不自动重发 POST。首次明确的 4xx 拒绝可结束意图，但已经不确定的请求后来收到拒绝仍保持待确认，不能据此断言此前没有执行。会话存储不可写时不发送；损坏的待确认记录阻止新操作，需核对任务历史后处理。

任务页支持 `PENDING / DISPATCHING / DELIVERED / RUNNING / RETRY_WAIT / SUCCEEDED / FAILED / UNKNOWN`。未知状态按 `UNKNOWN` 展示。来源分别显示真实 Docker、Agent 模拟、历史数据库模拟、来源未验证；模拟成功不会表述为真实容器已操作，未知来源不会显示成功提示。UNKNOWN 不自动重试或重做原命令；人工核对使用下一节的独立授权与记录。

点击任务读取 `GET /api/tasks/{id}` 和 `/events`，展示命令 ID、目标、发起人、投递次数、结果码、创建/更新/结束时间以及按顺序排列的事件。校验任务 ID 与事件身份、时间和递增序号；切换任务、离开任务页或退出会清空旧结果并拦截晚到响应。页面每 15 秒更新列表与当前详情，也可手动刷新；不是 WebSocket 推送。任务状态从不直接修改实例采集状态。

## 6. UNKNOWN 独立人工核对

实现遵循[UNKNOWN 任务人工核对设计](UNKNOWN任务人工核对设计.md)。任务详情保留原结果和事件，下面的“独立人工核对”单独读取原任务、核对能力、已有记录及独立事件。权限失败只关闭核对；全局只读、查看令牌、核对开关关闭或未获准实例不能提交。核对开关与容器动作控制独立，不能把核对当作启动、停止、重启。

首次提交前必须点击“读取确认前证据”，成功取得同任务 `review-evidence`，展示读取时间、绑定、原 Agent 记录、worker/已知进程和互斥条件。只有 `canAcknowledge=true`、本地权限通过、原因和人工证据有效、两个风险框分别勾选后才开放提交。缺记录、绑定变化、执行器活动或证据刷新失败均禁用，未知布尔值显示“未验证”。中央节点主键与 Agent 自报节点 ID 属于不同命名空间；顶层中央身份严格匹配，Agent 的原绑定由后端验证，不错误要求两个节点 ID 相等。

原因最多 500、证据最多 4000 个 Unicode 码点；CRLF/CR 转 LF，按 ECMAScript `trim` 去除首尾空白（含 NBSP、FEFF、全角空格），其余原文保留，拒绝 NUL 和未配对代理字符。证据只作纯文本展示，不执行内容、不访问其中 URL。两个确认项默认不选：不重放原命令，以及 CLI 退出后 Docker daemon 仍可能继续处理原请求的剩余风险。

核对独立生成 UUID 并在发送前保存在会话存储。POST 仅发送冻结的五个正文字段；只有 202 且目标、命令、原键、正文均匹配才认定“持久接收”，不代表解锁。刷新页面可从全局待确认提示恢复原任务，先 GET 现存记录，绝不自动 POST；网络异常或 409 保留原键。如果同任务已经有不同键的唯一记录，需要用户阅读已有正文、明确选择继续已有记录。核对 GET 返回原键和完整正文，接受后不依赖浏览器永久保留记录。

状态为 PENDING、PROCESSING、RETRY_WAIT、BLOCKED、APPLIED。BLOCKED 仅提供“按原核对请求重新检查”，复用 GET 的原键、原因、证据和两个 ACK，不产生新命令。APPLIED 显示“已人工核对并解除互斥，原执行结果仍不确定”；原 UNKNOWN/原事件不改，Agent 原终态与本次独立观察单列为证据，不能回填实例状态。当前任务 `blocksInstance=false` 只说明它不再占锁，不保证没有另一条新任务。后续动作必须重新确认、新 UUID、新 commandId；重查旧核对不能清除新锁。

核对区在原任务为 `PENDING/DISPATCHING/DELIVERED/RUNNING/RETRY_WAIT` 时每 15 秒只读刷新原任务、能力与核对记录，使同一详情中的结果和互斥状态跟进。原任务为 `SUCCEEDED/FAILED` 且没有核对记录后停止自动刷新；原任务进入 `UNKNOWN` 且尚无核对记录时也暂停，保留填写中的原因、人工证据、两个风险确认和已读取的确认前证据。已有核对记录或读取失败时继续原有轮询，提交期间不轮询。手动刷新核对记录会废弃旧的确认前证据，提交前须重新读取。切换任务、离开任务页、注销或换令牌会取消旧请求并拒绝晚到回调，清空屏幕上的证据和草稿，保留未确定的请求标识。此版本仍是基础令牌权限，不是完整 RBAC。

上述原任务状态轮询修复来自隔离真实 Docker 网页验收中的视觉发现：主详情已经成功，核对区却停在首次已排队。两项实际组件回归先复现旧问题，修复后相关 18 项测试及类型检查/构建通过，已于 12:13 随仅静态更新发布生产。原三次网页动作与物理容器证据保留，原 43 检查未覆盖此显示缺陷。新版后续真实页面回归已确认核对区自动跟随成功和自然 UNKNOWN，无手动刷新绕过问题；UNKNOWN 未提交草稿与确认前证据保持，轮询不产生写请求。
