# Argus 需求文档

更新时间：2026-09-30

## 1. 项目目标

Argus 是面向个人和小团队的服务器运维控制台，统一查看云主机、Minecraft 和其他 Docker 服务的状态，在权限和审计约束下执行受控操作。第一阶段先保证可观察、可追踪、可回滚，再逐步增加高并发、消息队列、监控和 AI/RAG。

## 2. 用户角色

| 角色 | 能力 |
|---|---|
| 管理员 | 管理节点、服务实例、任务、日志和部署配置 |
| 运维协作者 | 查看授权项目和执行被允许的操作 |
| AI 助手 | 读取授权证据、生成诊断和操作计划，不能直接执行 shell/Docker |

## 3. MVP 功能

1. 节点列表、在线状态和最后心跳。
2. 服务实例列表、版本、端口和运行状态。
3. 任务创建、状态机、结果和审计记录。
4. 日志查询、筛选和后续实时刷新。
5. H2 本地开发库与 MySQL 生产库切换。
6. Agent 健康、实例探测、日志读取和白名单动作接口。
7. 中文前端、中文开发资料、变量说明和数据库表说明。

## 4. 生产阶段功能

- Agent 注册、mTLS/令牌、权限 scope 和能力清单。
- Redis 在线状态/幂等/限流，RabbitMQ 异步任务与死信。
- Prometheus/Grafana/Loki 指标、日志和告警。
- 多用户权限、审批、操作确认和回滚。
- Adapter 机制接入 Minecraft、MySQL、Redis、Nginx、Java 服务和 OpenWebUI。
- WebSocket 实时事件和断线补偿。

## 5. AI/RAG 范围

AI 排在基础运维链路之后。AI 只能通过受控工具读取指标、日志、变更和文档，输出带证据的诊断与 `ActionPlan`。写操作必须经过权限和审批，执行仍由任务编排器与 Agent 完成。模型密钥只从运行环境注入，不写入项目、日志和备份。

## 6. 安全与可靠性要求

- 所有危险操作必须有权限、幂等键、超时、审计和回滚。
- Minecraft 容器、世界目录和数据库变更前必须备份并校验。
- 生产数据库关闭演示数据自动写入。
- Docker socket 只给 Agent，浏览器和 AI 不直接访问。
- 公网只暴露必要的网站和游戏端口；管理、数据库、队列和监控端口走白名单或内网。
- 节点资源不足时，扩容或完成容量治理后再新增大型镜像和构建任务。

## 7. 验收方式

- 本地：前端构建、后端测试、Agent 编译和健康检查通过。
- 部署：网站通过已配置的实际域名访问，控制中心健康检查正常，数据库迁移可追踪；文档域名仅作示例。
- 服务器：Agent 只读探测正确，Minecraft 未授权操作不会发生，备份可恢复。
- AI：回答必须引用证据，无法检索到证据时明确说明未知。

## 8. 部署端口约束模板

以下为角色和端口示例，不代表任何现网的监听或防火墙状态：

- 网站入口：网站节点 TCP 80/443，正式发布前配置 HTTPS 和适用的域名接入要求。
- 控制中心：示例仅监听网站节点本机 TCP 9091，不对公网直连。
- Agent：示例 TCP 8090，只允许控制中心来源或通过受控内网连接；同机 Agent 可走本机。
- MySQL：示例 TCP 3306，只允许控制中心及必要管理来源，按实际网络配置安全组。
- Minecraft：只开放实际运行容器所需的游戏端口，不按历史 DNS 记录自动开放端口。
