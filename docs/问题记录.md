# 未序 Argus 问题记录

更新日期：2026-10-07。本文件仅记录可从源码确认的产品和工程缺口，部署环境的问题应记录在仓库外的私有运维记录中。

## 待解决问题

| 优先级 | 问题 | 当前表现 | 完成标准 |
|---|---|---|---|
| P0 | 用户权限与审计不完整 | 只有可选 Bearer 令牌与只读保护，没有用户/角色授权或完整操作审计 | 权限在服务端校验；重要操作可追溯；凭据具备轮换与撤销流程 |
| P0 | 任务状态不代表真实执行 | `TaskService` 调用实例服务修改数据库，未调用 Agent 执行任务 | 任务关联节点与实例，执行、结果回传、失败与超时处理可端到端验证 |
| P0 | 多节点实例 ID 冲突 | 快照按容器/实例 ID 全局保存，未采用节点作用域 | 数据迁移完成，同名容器在不同节点上独立展示、查询与操作 |
| P1 | Agent 任务不持久化 | 任务结果保存在内存，进程退出后丢失 | 有持久化 Inbox/执行记录，重启恢复与重复投递可验证 |
| P1 | 日志页面未接入实时采集 | `/api/logs` 查询 `logs` 表；Agent 日志读取是独立链路 | 页面可明确查询目标节点和实例，显示真实日志或真实错误，保留权限限制 |
| P1 | 指标存在默认值 | 玩家数未真实采集；前端缺少 TPS 时默认 20；部分采集失败返回 0 | 引入指标可用性、来源和时间戳；未采集值不展示为正常实测值 |
| P1 | 离线与数据新鲜度不足 | 同步按默认 60 秒固定延迟轮询，失败标记节点离线但保留实例快照 | 页面能区分最近快照与当前状态，超时、延迟和断连有明确语义 |
| P1 | 真实备份恢复尚未形成验收闭环 | 有备份模板与操作说明，压缩完整性检查不等于可恢复 | 在隔离位置完成恢复演练并记录版本、校验、恢复耗时和业务验证 |
| P2 | 企业级组件尚未接入 | Redis、消息队列及多实例协调只有设计 | 基于具体负载实现并验证，不以依赖存在作为验收 |
| P2 | 监控平台未接入 | 仅有 Agent `/metrics`，无历史存储与告警 | 抓取、查询、告警触发与恢复链路可验证 |
| P2 | AI/RAG 未实现 | 只有角色形象与设计资料 | 知识来源可追溯、回答有证据；执行动作仍经过权限与审批 |

P0 表示开放真实管理操作或扩展多节点之前应优先处理，并不表示本文执行了任何远端变更。

## 已具备的保护

- 生产用途配置应保持 `ARGUS_API_READ_ONLY=true`，Agent 保持 `control.enabled=false`。
- Agent 网关默认关闭；启用时要求认证令牌与目标白名单。
- HTTP 请求体、线程、并发任务数有上限，Docker 执行使用参数数组与超时。
- 前端生产构建不会用演示数据掩盖 API 故障；开发模式的演示回退不能用于验收真实连接。
- MySQL profile 默认关闭演示数据初始化，避免把本地示例插入真实环境。

这些保护用于限制当前 MVP 的影响范围，不能代替用户权限、审计、任务可靠性和网络隔离。
