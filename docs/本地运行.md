# 未序 Argus 本地运行

需要 JDK 17、Maven 3.9+、Node.js 与 npm。默认启动和自动化测试使用本地 H2 与 mock Agent，不需要服务器或数据库凭据。

## 启动

在仓库根目录分别打开三个终端：

```powershell
.\scripts\start-backend.ps1
```

```powershell
.\scripts\start-agent.ps1
```

```powershell
.\scripts\start-frontend.ps1
```

默认本地入口：

| 模块 | 地址 |
|---|---|
| Web 管理台 | `http://localhost:5173` |
| 控制中心 | `http://localhost:8080` |
| 节点 Agent | `http://localhost:8090` |

Agent 默认 `executor.mock=true`，不调用 Docker；远程动作默认关闭。控制中心的 Agent 网关也默认关闭，独立启动三个模块不等于已经启用 Agent 同步。

前端只有 Vite 开发模式允许读取演示数据。生产构建遇到 API 故障会报错，不回退为演示成功；401 授权失败在开发模式也不会被演示数据掩盖。

## 数据存储与 MySQL

控制中心默认使用 `./data/argus` 的 H2 文件库，该相对路径以后端进程工作目录为基准。启动时 Flyway 应用 `backend/src/main/resources/db/migration/` 中的迁移；本地配置默认初始化演示数据。

使用 MySQL 时，`MYSQL_HOST`、`MYSQL_DATABASE`、`MYSQL_USER` 和 `MYSQL_PASSWORD` 必须由运行环境注入；`MYSQL_PORT` 默认 `3306`。不要修改源码中的占位符。配置好个人运行环境后执行：

```powershell
mvn -f backend/pom.xml spring-boot:run '-Dspring-boot.run.profiles=mysql'
```

MySQL profile 默认关闭演示数据并开启 API 只读保护。这里没有预先创建或共享的数据库，部署者需要准备自己的环境。

在 IDEA 中导入 `backend/pom.xml`，使用 JDK 17；打开 `Run → Edit Configurations`，选择 `Application` 或 `Spring Boot` 配置，启动类为 `com.argus.controlcenter.ArgusControlCenterApplication`，模块为 `argus-control-center`，工作目录为项目的 `backend` 目录。在该配置的环境变量中填写 `SPRING_PROFILES_ACTIVE=mysql` 和 `MYSQL_*`，不勾选 `Store as project file`。完整步骤见 [数据库接入](数据库接入.md)。

本地与 Git 保持同一份占位符源码，个人连接信息只留在未共享的 IDEA 运行配置中。

## 验证

```powershell
Invoke-RestMethod http://localhost:8080/api/health
Invoke-RestMethod http://localhost:8090/api/agent/health
mvn -f backend/pom.xml test
npm --prefix frontend ci
npm --prefix frontend run build
```

后端测试使用 H2 内存库；网关测试使用本机临时 mock HTTP 服务。不要给测试复用 MySQL 运行配置或注入真实连接。上述检查通过只代表本地测试与构建通过，真实 MySQL 需要在隔离测试库另行验证。

开启网关需配置节点记录、允许访问的主机与匹配令牌。当前快照由控制中心定时拉取，不是 Agent 主动上报；任务只修改控制中心数据库状态，日志页面只查询日志表。真实控制和日志闭环的缺口见 [问题记录](问题记录.md)。

不要为了验证页面而开启真实容器控制。需要真实采集时，先阅读 [Agent 说明](../agent/README.md) 和 [交接文档](交接文档.md)。
