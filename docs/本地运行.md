# 未序 Argus 本地运行

更新：2026-10-08。产品工程使用 JDK 17、Maven 3.9+、Node.js 和 npm。默认运行 H2 与 mock Agent，不需要远程服务器凭据。

## 启动

在仓库根目录分别打开三个终端：

```powershell
.\scripts\start-backend.ps1
```

```powershell
.\scripts\start-agent.ps1
```

```powershell
.\scripts\start-frontend.ps1
```

| 模块 | 默认本地入口 |
|---|---|
| Web 管理台 | `http://localhost:5173` |
| 控制中心 | `http://localhost:8080` |
| Agent | `http://localhost:8090` |

Agent 默认 mock，不调用 Docker，远程动作关闭。中央网关默认关闭，启动三个进程不等于已启用采集。后端本地演示数据标为 MOCK；前端开发/生产都不把 API 错误替换为演示成功。

## 数据存储与 IDEA

H2 文件库 `./data/argus` 相对后端工作目录，换工作目录会改变数据位置。Flyway 执行 resources 中 V1–V3 SQL 和 `src/main/java/db/migration/` 的 V4/V5 Java 迁移。

MySQL profile 需要 `MYSQL_HOST`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`，端口 `MYSQL_PORT` 默认 3306。源码保留占位符；在 IDEA 的个人运行配置中填写环境变量，不勾选 `Store as project file`。

导入 `backend/pom.xml`，选 JDK 17，启动类为 `com.argus.controlcenter.ArgusControlCenterApplication`，模块为 `argus-control-center`，工作目录选 `backend`。加入 `SPRING_PROFILES_ACTIVE=mysql`，并保持演示关闭、API 只读、网关关闭；详情见 [数据库接入](数据库接入.md)。

由个人运行环境注入变量后，也可执行：

```powershell
mvn -f backend/pom.xml spring-boot:run '-Dspring-boot.run.profiles=mysql'
```

本地与 Git 使用同一份模板；不要在源码中另存真实连接。

## 开启本地只读联调

先在受控初始化中登记节点，再配置中央网关主机白名单、匹配 Agent 令牌及启用开关；保持网关只读、Agent `control.enabled=false`。节点 API 写入受只读保护，不要为了联调取消认证或主机白名单。

启用后中央每轮结束等待 60 秒采集；网页默认每 15 秒读取中央数据。实例由中央 ID 唯一定位，同名容器按节点区分。日志页先选实例，再调用新中央日志接口；网关未启用时会显示真实错误，不回退空日志。可靠任务另有默认关闭开关，不再运行中央数据库模拟成功流程。

## 本机 mock 任务联调

仅在隔离本机环境启用，真实 Docker 保持关闭。完整约束见[可靠任务接口与恢复约定](可靠任务接口与恢复约定.md)，环境值由个人运行配置注入，不在示例填写凭据。

| 配置层 | 本机联调要求 |
|---|---|
| 中央认证 | 开启 `ARGUS_API_AUTH_REQUIRED`，使用非空且不同的 `ARGUS_API_ACCESS_TOKEN` / `ARGUS_API_CONTROL_TOKEN`；控制验证时全局只读关闭 |
| 中央任务 | `ARGUS_TASK_CONTROL_ENABLED=true`；`ARGUS_TASK_ALLOWED_INSTANCE_IDS` 仅列明确的中央 ID；`ARGUS_TASK_ALLOW_DOCKER=false` |
| Agent 通道 | 开启网关、保留 GET 网关只读及主机白名单；`ARGUS_AGENT_GATEWAY_ALLOW_CONTROL=true`；读取与控制令牌不同且与 Agent 匹配 |
| Agent 执行 | `executor.mock=true`，`control.enabled=true`，独立非空令牌、`ARGUS_AGENT_CONTROL_INSTANCES` 明确列出局部 ID |
| 持久身份 | 稳定 node.id，每个 Agent 使用独立 `ARGUS_AGENT_TASK_DIR`；目录在项目私有测试区域，禁止共享或随意删除 |

网页用同一输入框切换查看/操作令牌。先查询控制能力，再确认节点、实例、模式和风险；202 只代表接收，详情和事件页观察最终结果。超时后保留原键核对，UNKNOWN 只能查询，不得新建操作绕过互斥。结束隔离测试后关闭临时进程和控制配置，不能复用测试开关发布生产。

若通过 IP 与非标准端口访问，CORS 来源必须精确包含协议和端口，例如部署者配置 `ARGUS_CORS_ORIGINS=http://192.0.2.10:9090`（TEST-NET 占位地址）。代理的 Host 与转发协议应对应浏览器入口，Nginx 非标准端口转发可保留 `$http_host`，必要时正确传递 `X-Forwarded-Proto`；不要为排查 403 把来源放宽为任意站点。403 也可能来自 Origin 与后端感知入口不一致，应与令牌拒绝区分。

## 验证

```powershell
mvn -f backend/pom.xml test
.\scripts\test-agent.ps1
npm --prefix frontend test
npm --prefix frontend run build
```

第一次准备前端依赖可运行 `npm --prefix frontend ci`。本轮复用既有依赖，版本和结果见 [开发进度](开发进度.md)。

后端默认用 H2 与本机 mock；MySQL 专项通过独立 `ARGUS_TEST_MYSQL_*` 配置本机一次性空库，未配置时跳过。不要复用应用 MySQL 运行环境。Agent 检查使用模拟 Docker、Java 测试子进程和本机 HTTP；前端浏览器检查也使用隔离接口。

这些检查不等于真实 Docker、远程部署、负载或恢复验收。本轮未部署；需要实际采集前先看 [Agent 说明](../agent/README.md)、[验收清单](验收清单.md) 和 [交接文档](交接文档.md)。
