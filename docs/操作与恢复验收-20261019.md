# 操作与恢复验收：2026-10-19

## 范围与结论

本轮通过浏览器访问云服务器上的独立控制中心，连接真实 Agent、独立 MySQL、真实 Docker 测试容器。它是云端隔离验收，**不是生产游戏服操作测试，也不是整个项目已发布**。

常规操作/恢复流程 17 项检查通过；浏览器响应丢失、双击和原键核对专项 9 项检查通过。原始结果、截图及私有配置位于本地 `local-private/stage2-acceptance-20261019/`，不纳入公开仓库。

另完成在途中央重启专项：真实 Agent 的 RESTART 记录处于 RUNNING 时重启控制中心，恢复后原任务 SUCCEEDED，Agent 进程未变，原 commandId 只有一条 Inbox，浏览器核对该任务仅一次 Agent POST。专项网页流程 10 项检查通过。摘要见 [重启证据](验收证据/20261019/restart-control.json) 和 [浏览器记录](验收证据/20261019/browser-restart.json)。

## 环境边界

- 控制中心、Agent、验收代理均绑定云服务器 loopback，通过 SSH 转发供本地浏览器访问。
- 唯一允许操作的中央实例：`acceptance-instance`；唯一允许操作的 Docker 容器：`argus-acceptance-fixture`。
- 独立数据库：`argus_test_acceptance`；独立 MQ 实例。没有向生产库插入这些任务。
- Agent 操作令牌与读取令牌分开；中央 API 同样分开。实际令牌仅在忽略目录和服务器私有配置中。
- 操作前后对比真实游戏容器 ID、StartedAt 和运行状态；最终核对 `gameBaselineUnchanged=true`。

## 实际执行了什么

| 场景 | 方法 | 观测结果 |
|---|---|---|
| 正常 START/RESTART/STOP | 网页实例行 → 确认真实 Docker 模式 → 提交 → 任务详情 | 3 条任务均 SUCCEEDED；每条最后事件与终态一致 |
| Agent 接纳回执丢失 | 固定代理转发一次 POST，隐藏响应及原命令后续查询 | 中央到达 UNKNOWN；Agent POST 增量为 1 |
| UNKNOWN 人工核对 | 网页读取证据、填写原因和证据、勾选两项风险确认、提交 | 独立核对 APPLIED；原任务仍 UNKNOWN；没有新增容器命令 |
| 核对后继续操作 | 新建 STOP 任务 | SUCCEEDED，证明原互斥已按核对流程解除 |
| 浏览器 202 丢失 | 浏览器拦截先让服务器持久接收，再丢弃响应 | 页面保留待确认意图，未当成失败创建新任务 |
| 连续双击确认 | 在同一事件周期连续触发确认按钮 | 加上响应丢失场景，最终仅新增 1 条任务 |
| 刷新页面恢复 | 页面 reload 后点击“用原请求核对” | Idempotency-Key 完全相同，返回原 taskId；Agent 仅收到 1 次投递 |
| 节点离线及恢复 | 代理只对测试 Agent health 注入 503，再恢复 | NODE_OFFLINE 触发 ACTIVE 后恢复 RESOLVED；浏览器明确显示已恢复 |

常规流程原始结果：`browser-operations-passed.json`；网络专项：`browser-network-passed.json`；物理与存储核对：`server-evidence.txt`。

最终取证时，中央累计 14 条隔离测试任务，对应 14 个校验通过的 Inbox 文件；测试实例未决锁为 0，物理测试容器为停止状态。这些累计数包含失败排查及重复复验，**不能说成一次用户流程执行了 14 条命令**。

在途重启复验后再次取证，累计为 17 条任务/17 个 Inbox，逐条关联 commandId、动作与允许容器一致；未决锁仍为 0，测试容器已停止，游戏容器基线未变。见 [物理与 Inbox 摘要](验收证据/20261019/docker-inbox.json)。

## 本轮失败与修复也保留

1. 初始测试脚本写死实例展示名，而初始化名称不同，定位器失败，未发送动作。改成按固定实例 ID 查找并读取当前名称。
2. 采集读取预算 1 秒不足以覆盖 Docker stats，出现 PARTIAL；隔离配置调整为 5 秒，并将中央任务租约设为 20 秒，超过三次完整 HTTP 预算。
3. 测试 Agent 的命令超时 5 秒，而测试 shell 容器停止需等待 Docker 默认约 10 秒，重启进入 EXECUTION_UNCERTAIN。保留原任务，通过网页人工核对处理，没有直接删锁或改成功。
4. 将隔离 Agent 命令超时改为 20 秒、命令 TTL 30 秒、确认宽限 10 秒，随后正常启停重启通过。这些是验收配置，不替代源码默认值。
5. 截图曾在异步刷新完成前拍摄，不能证明恢复显示；脚本增加等待并断言页面显示“正常 / 已恢复”，复验通过。
6. 测试初始化 mysql 客户端未指定 UTF-8，导致中文标签异常；初始化脚本显式使用 utf8mb4，并只修复测试节点/实例标签。

## 对应脚本与代码

- `scripts/acceptance/server-fixture.py`：限定测试服务和数据库、初始化、基线与 Inbox 校验；不操作游戏容器。
- `scripts/acceptance/fault-proxy.py`：固定目标 loopback 代理；受鉴权的 health/回执故障注入，没有通用 URL 转发能力。
- `scripts/acceptance/browser-check.cjs`：真实网页确认、故障、核对、页面重载与同键恢复。
- `TaskQueueStore` / `TaskWorker`：中央持久接收、领取、查询原命令、结果与互斥。
- Agent `TaskService` / `TaskInbox`：持久去重、执行与恢复证据。
- `TaskReviewIntegrationTest`：本轮完整后端回归中 20 项通过，覆盖旧回执不能清新锁、租约竞争、核对事务回滚等。此类测试使用可控 Agent 协议替身，不伪装成真实 Docker 结果。

## 尚未被本报告证明的事项

- 本报告没有在真实 Docker 运行中强杀 Agent 并证明机器崩溃恢复；已有恢复测试与本轮正常进程重启数据保留需要分别说明。
- 本报告没有验证跨节点容灾、磁盘永久损坏、任意规模高并发或生产控制全面启用。
- 阶段②的当前轮次主要操作与人工恢复闭环有证据，严格的在途重启专项仍需补充，不因此直接勾选整个项目完成。
