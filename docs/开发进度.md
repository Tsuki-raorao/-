## 当前结论

基础只读 MVP 已具备，多节点身份、可信采集和最近日志保留。本轮可靠任务实现已落地：中央持久排队、Agent 持久接收/恢复、基础操作授权、网页确认与任务事件。**Agent、后端和前端模块检查及本机实际跨模块 28 项断言均通过。尚未部署，未操作真实 Docker；完整权限审计、UNKNOWN 人工核对流程、MQ 和 AI 仍未完成。** 统一说明见 [项目说明与进度汇报](项目说明与进度汇报.md)。

### 可靠任务的实现范围

按 [冻结契约](可靠任务接口与恢复约定.md)，中央原来的数据库模拟成功已被持久队列替代，HTTP 202 只表示接收；Task、队列、实例互斥和追加事件在事务内保存。重复提交使用原幂等键，中央投递使用固定 commandId。Agent 原子文件保存 Inbox，PENDING 可恢复，RUNNING 崩溃转 UNKNOWN，不重放。任务结果不修改实例采集值，历史任务为 LEGACY_MOCK 且不生成投递。保证重复传输去重和保守的进程恢复，不承诺 Docker 副作用 exactly-once 或跨平台断电一致性。

前端依赖未升级，复用已安装依赖；锁定版本为 Vue 3.5.43、TypeScript 5.7.3、Vite 6.4.3，运行工具为 Node.js 22.23.1、npm 10.9.8。产品 Java 基线仍为 17。未配置 `ARGUS_TEST_MYSQL_*` 时，普通后端测试会跳过 MySQL 专项，不应报告为全部测试均实际执行。

本轮 28 项实际联调包括：浏览器确认目标、HTTP 202、详情/事件/模拟结果；同名实例分属不同节点；同键并发只产生一个命令投递；只读及查看/操作令牌边界；丢失接受回应后停止中央并重启 Agent，恢复时只查询原结果、不再次 POST；更换全新 Inbox 后 storeId 变化进入 UNKNOWN 并保持互斥。测试的临时 Java、Edge、MySQL 进程已停止，这不是线上排障或真实容器操作记录。

本轮没有连接真实 Docker、远程服务器或修改生产环境，没有执行负载测试或业务恢复演练。源码、模块测试、跨模块测试、历史部署与今日在线状态应分别记录。

上一轮只读基线：后端 29 项分两次实际通过（H2/mock 28、隔离 MySQL 专项 1）；前端 17 项与 Edge 14 类；双 Java mock Agent、打包后端和隔离 MySQL 的 22 项跨模块断言通过。它们验证 V4 身份、采集和日志，不能代替本轮 V5 可靠任务验收。更早的 8 项后端测试和 10 月 7 日构建亦仅为历史记录。
