# 未序 Argus 数据库接入

控制中心支持本地 H2 和 MySQL。本文提供通用配置，不包含任何运行环境的连接信息。

## 默认本地 H2

默认配置位于 `backend/src/main/resources/application.yml`，使用相对路径的 H2 文件库 `./data/argus`。数据实际存放位置取决于后端进程的工作目录；交接时应固定工作目录，避免误以为切换目录后数据丢失。

本地默认启用演示数据。启动时 Flyway 自动应用 `backend/src/main/resources/db/migration/` 中的迁移，节点、实例、任务、日志通过 JdbcTemplate 持久化。

## 使用 MySQL

启用 `mysql` profile，连接参数从环境变量读取：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `MYSQL_HOST` | 无，必填 | 数据库地址，仅在个人运行配置中填写 |
| `MYSQL_PORT` | `3306` | 数据库端口 |
| `MYSQL_DATABASE` | 无，必填 | 应用数据库名 |
| `MYSQL_USER` | 无，必填 | 应用数据库账户 |
| `MYSQL_PASSWORD` | 无，必填 | 应用数据库密码 |
| `ARGUS_DEMO_DATA_ENABLED` | `false` | MySQL profile 是否插入演示数据 |
| `ARGUS_API_READ_ONLY` | `true` | MySQL profile 的 API 只读保护 |

源码使用 `${MYSQL_HOST}`、`${MYSQL_DATABASE}`、`${MYSQL_USER}`、`${MYSQL_PASSWORD}` 必填占位符，端口使用 `${MYSQL_PORT:3306}`。不要把占位符改成真实值；缺少必填变量时应先补充运行配置，再启动 MySQL profile。

### 在 IntelliJ IDEA 中配置

1. 导入 `backend/pom.xml`，为后端模块选择 JDK 17。
2. 打开 `Run → Edit Configurations`（运行 → 编辑配置），新增 `Application`；已有 `Spring Boot` 配置也可使用。
3. Main class 填 `com.argus.controlcenter.ArgusControlCenterApplication`，Classpath/module 选择后端模块 `argus-control-center`，Working directory 选择项目的 `backend` 目录。
4. 在 `Environment variables`（环境变量；若未显示，在 `Modify options` 中启用）加入 `SPRING_PROFILES_ACTIVE=mysql`，并填写上表的五个 `MYSQL_*` 变量。真实值仅保存在该个人运行配置中。
5. 保持 `ARGUS_DEMO_DATA_ENABLED=false`、`ARGUS_API_READ_ONLY=true`、`ARGUS_AGENT_GATEWAY_ENABLED=false`。不要勾选 `Store as project file`，不要导出或分享包含凭据的配置。

本地和 Git 使用同一份占位符源码，不再另存一套填写真实连接的代码。默认不设置 `mysql` profile 时仍使用 H2；测试不要复用上述 MySQL 运行配置。

由本机环境或秘密管理工具注入上述变量后运行，不把真实值写入命令记录或项目文件：

```powershell
mvn -f backend/pom.xml spring-boot:run '-Dspring-boot.run.profiles=mysql'
```

或打包后运行：

```powershell
mvn -f backend/pom.xml package
java -jar backend/target/argus-control-center-0.1.0-SNAPSHOT.jar --spring.profiles.active=mysql
```

环境文件的字段模板见 `deploy/systemd/argus-control-center.env.example`。模板不是现成连接配置；实际部署环境文件保存在仓库外并限制读取权限。

## 表与迁移

| 迁移 | 内容 |
|---|---|
| V1 | `nodes`、`instances`、`tasks`、`logs` 与索引、外键 |
| V2 | 实例 CPU、内存与玩家数字段 |
| V3 | 节点 CPU、已用内存与总内存字段 |

Flyway 使用 `flyway_schema_history` 记录迁移。字段存在不代表指标已有真实采集，例如玩家数目前仍缺少采集实现。详细定义见 [数据库表文档](../backend/docs/数据库表文档.md)。

当前实例主键尚未带节点作用域，接入多节点前应先处理同名实例冲突。`tasks` 表保存控制中心的任务记录；当前任务成功状态不代表 Agent 已执行 Docker 操作。

## 接入验证

日常自动化测试使用隔离的 H2 内存库与本机 mock Agent，不需要真实数据库凭据。通过 H2 测试不等于通过真实 MySQL 验证；MySQL 的版本、权限、迁移兼容性与连接可用性需要在独立测试库单独验证。

1. 确认数据库可从控制中心网络访问；入口仅允许必要来源。
2. 确认应用账户的授权范围与迁移需求，避免复用服务器管理账户。
3. 启动后检查 Flyway 结果，并请求 `/api/health` 验证 `databaseReady`。
4. 保持演示数据关闭和 API 只读，在隔离测试库验证迁移与重启持久化。
5. 迁移前完成备份，恢复演练在独立测试库执行；不要直接覆盖业务库。

备份模板见 `deploy/database/backup-argus-mysql.sh`。数据库导出包含运行数据，不应进入公开仓库。
