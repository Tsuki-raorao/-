# Argus 数据库表文档

当前结构由 `src/main/resources/db/migration/V1__create_argus_tables.sql`、V2 实例指标和 V3 节点指标迁移建立。字段名使用下划线，Java 字段使用驼峰命名；时间统一由 `Instant` 表示，JDBC 映射为 `TIMESTAMP`。

## 1. 表关系

```text
nodes 1 ─── N instances 1 ─── N tasks
                         └──── N logs
```

一个节点可以承载多个服务实例；一个实例可以产生多次控制任务和多条日志摘要。删除策略当前没有开放级联删除，避免误删历史审计数据。

## 2. 表说明

### `nodes`：服务器节点

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `name` | `VARCHAR(128)` | 否 | 节点显示名 |
| `address` | `VARCHAR(255)` | 否 | Agent/主机地址 |
| `status` | `VARCHAR(16)` | 否 | `ONLINE/OFFLINE/UNKNOWN` |
| `last_heartbeat` | `TIMESTAMP` | 是 | 最近心跳 |
| `cpu_percent` | `DECIMAL(10,2)` | 否 | Agent 最近一次主机 CPU 瞬时占用百分比，采集失败为 0 |
| `memory_bytes` | `BIGINT` | 否 | Agent 最近一次主机已用内存字节数，采集失败为 0 |
| `memory_total_bytes` | `BIGINT` | 否 | Agent 最近一次主机内存总字节数，采集失败为 0 |

### `instances`：服务实例

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `name` | `VARCHAR(128)` | 否 | 实例名称 |
| `node_id` | `VARCHAR(64)` | 否 | `nodes.id` 外键 |
| `container_name` | `VARCHAR(128)` | 否 | 容器名称 |
| `version` | `VARCHAR(64)` | 否 | 应用/游戏版本 |
| `status` | `VARCHAR(16)` | 否 | 实例生命周期状态 |
| `updated_at` | `TIMESTAMP` | 否 | 最近状态变化时间 |
| `cpu_percent` | `DECIMAL(10,2)` | 否 | Agent 最近一次 CPU 瞬时占用百分比，采集失败为 0 |
| `memory_bytes` | `BIGINT` | 否 | Agent 最近一次内存占用字节数，采集失败为 0 |
| `player_count` | `INT` | 否 | 服务报告的玩家数量，非游戏服务为 0 |

索引：`idx_instances_node_id(node_id)`，用于按节点查询实例。

### `tasks`：控制任务

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `instance_id` | `VARCHAR(64)` | 否 | `instances.id` 外键 |
| `action` | `VARCHAR(32)` | 否 | START/STOP/RESTART |
| `status` | `VARCHAR(16)` | 否 | 任务状态机状态 |
| `message` | `VARCHAR(512)` | 是 | 结果或错误说明 |
| `created_at` | `TIMESTAMP` | 否 | 创建时间 |
| `finished_at` | `TIMESTAMP` | 是 | 结束时间 |

索引：`idx_tasks_instance_created(instance_id, created_at)`，用于查询实例任务时间线。

### `logs`：日志摘要

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `instance_id` | `VARCHAR(64)` | 否 | `instances.id` 外键 |
| `log_timestamp` | `TIMESTAMP` | 否 | 日志发生时间 |
| `level` | `VARCHAR(16)` | 否 | INFO/WARN/ERROR 等 |
| `message` | `VARCHAR(4000)` | 否 | 清洗后的摘要内容 |

索引：`idx_logs_instance_timestamp(instance_id, log_timestamp)`，用于按实例倒序读取日志。

## 3. 迁移和备份要求

- V3 只追加节点运行时指标列，旧数据默认 0；不能修改已经执行的 V1/V2 文件。
- 生产执行 V3 前先备份 MySQL，部署后检查 Flyway 版本、`/api/health` 和 `/api/nodes`；指标为 0 时表示 Agent 或主机接口没有提供可用快照。

- 已执行的迁移文件不得修改；新结构新增 `V{数字}__{说明}.sql`。
- 生产迁移前备份 MySQL，并在部署记录中保存 Flyway 版本。
- 数据库不保存密码、私钥、模型 API Key；这些信息只放在运行时密钥系统。
- 原始高容量日志和指标不写入 `logs` 表，后续使用 Loki/Prometheus，MySQL 只保留摘要、索引和审计信息。
