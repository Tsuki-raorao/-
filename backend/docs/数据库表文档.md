# Argus 数据库表文档

当前结构由 V1–V3 SQL、V4 身份/采集迁移与 V5 持久任务迁移建立，两个 Java 迁移均在 `src/main/java/db/migration`。字段名使用下划线，Java 字段使用驼峰命名，时间由 `Instant` 表示。V4 新增采集时间、V5 新增任务/租约时间使用 `TIMESTAMP(6)`；固定 expiresAt 入库前截断至微秒，避免首次请求和重试序列化不同。

## 1. 表关系

```text
nodes 1 ─── N instances 1 ─── N tasks
                         └──── N logs
                    tasks 1 ─── 0..1 task_queue
                          1 ─── N task_events
                instances 1 ─── 0..1 instance_task_locks ─── 1 tasks
```

一个节点承载多个服务实例，一个实例产生多次任务和日志摘要。外键没有 `ON DELETE CASCADE`。业务 `NodeService.delete` 在父节点加锁后检查任何历史任务，有记录就返回 409，保护审计；只有没有任务时才显式删除日志、实例和节点。查看令牌不能删除，生产全局只读仍阻止操作令牌删除。

## 2. 表说明

### `nodes`：服务器节点

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `name` | `VARCHAR(128)` | 否 | 节点显示名 |
| `address` | `VARCHAR(255)` | 否 | Agent/主机地址 |
| `status` | `VARCHAR(16)` | 否 | `ONLINE/OFFLINE/UNKNOWN` |
| `last_heartbeat` | `TIMESTAMP` | 是 | 最近健康成功时间；失败不推进 |
| `cpu_percent` | `DECIMAL(10,2)` | 是 | 主机 CPU；真实 0 与缺失 NULL 不同 |
| `memory_bytes` | `BIGINT` | 是 | 已用内存字节数；NULL 表示本次不可用 |
| `memory_total_bytes` | `BIGINT` | 是 | 总内存字节数 |
| `last_checked_at` | `TIMESTAMP(6)` | 是 | 最近一次采集尝试，包括失败 |
| `last_successful_sync_at` | `TIMESTAMP(6)` | 是 | 完整清单持久化成功的批次时间 |
| `sync_status` | `VARCHAR(16)` | 否 | UNKNOWN / OK / PARTIAL / FAILED |
| `sync_error_code` | `VARCHAR(64)` | 是 | 固定脱敏错误码，不保存远端错误正文 |

### `instances`：服务实例

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 中央 ID；旧 ID 保留，新发现使用 UUID |
| `agent_instance_id` | `VARCHAR(64)` | 否 | Agent 局部 ID，仅在所属节点内唯一 |
| `name` | `VARCHAR(128)` | 否 | 实例名称 |
| `node_id` | `VARCHAR(64)` | 否 | `nodes.id` 外键 |
| `container_name` | `VARCHAR(128)` | 否 | 容器名称 |
| `version` | `VARCHAR(64)` | 否 | 应用/游戏版本 |
| `status` | `VARCHAR(16)` | 否 | 实例生命周期状态 |
| `updated_at` | `TIMESTAMP` | 否 | 最近状态变化时间 |
| `cpu_percent` | `DECIMAL(10,2)` | 是 | 容器 CPU；允许多核下大于 100 |
| `memory_bytes` | `BIGINT` | 是 | 容器内存字节数 |
| `player_count` | `INT` | 是 | 未支持时 NULL；真实无人在线才为 0 |
| `last_seen_at` | `TIMESTAMP(6)` | 是 | 在完整清单中出现的中央观测时间，同批等于节点成功时间 |

索引：`idx_instances_node_id(node_id)`，以及唯一索引 `uq_instances_node_agent(node_id, agent_instance_id)`。Agent 局部 ID 大小写敏感，MySQL 使用 `utf8mb4_bin`，H2 保持默认大小写敏感语义。

`nodes` 与 `instances` 共用以下采集字段：

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `data_source` | `VARCHAR(16)` | 否 | HOST / DOCKER / MOCK / LEGACY / UNKNOWN |
| `sampled_at` | `TIMESTAMP(6)` | 是 | Agent 采样尝试时间；旧协议没有可信新时间 |
| `metrics_status` | `VARCHAR(16)` | 否 | AVAILABLE / PARTIAL / UNAVAILABLE / UNKNOWN |

HTTP/解析失败保留此前指标和 `sampled_at`；有效响应中不可用的指标为 NULL。V3 旧值原样保留，但标记 `LEGACY/UNKNOWN`，新增采样和观测时间为 NULL，不能作为已验证的新采样使用。

### `tasks`：控制任务

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `instance_id` | `VARCHAR(64)` | 否 | `instances.id` 外键 |
| `action` | `VARCHAR(32)` | 否 | START/STOP/RESTART |
| `status` | `VARCHAR(16)` | 否 | 任务状态机状态 |
| `message` | `VARCHAR(512)` | 是 | 结果或错误说明 |
| `created_at` | `TIMESTAMP` | 否 | 创建时间 |
| `finished_at` | `TIMESTAMP` | 是 | 结束时间 |
| `node_id` | `VARCHAR(64)` | 是（兼容旧表） | 接受时中央节点身份；旧数据从实例回填 |
| `agent_instance_id` | `VARCHAR(64)` | 是（兼容旧表） | 接受时远端局部身份 |
| `command_id` | `VARCHAR(36)` | 是 | 唯一 UUID；旧任务 NULL，不自动分配 |
| `idempotency_key` | `VARCHAR(36)` | 是 | 浏览器规范 UUID，全局唯一；旧任务 NULL |
| `execution_mode` | `VARCHAR(16)` | 否 | 默认 LEGACY_MOCK；新任务 MOCK/DOCKER |
| `requested_by` | `VARCHAR(32)` | 否 | 默认 legacy；新任务 operator |
| `updated_at` | `TIMESTAMP(6)` | 是（兼容旧表） | 状态变更时间，旧记录回填完成或创建时间 |
| `attempts` | `INT` | 否 | POST 尝试次数，默认 0 |
| `result_code` | `VARCHAR(64)` | 是 | 协议结果码；旧任务 LEGACY_MOCK |
| `target_address` | `VARCHAR(512)` | 是 | 不可漂移的规范化 Agent 地址，仅内部 |
| `agent_node_id` | `VARCHAR(128)` | 是 | Agent 自报身份，不同于中央 node_id |
| `store_id` | `VARCHAR(128)` | 是 | Agent 持久 Inbox 身份，仅内部 |
| `expires_at` | `TIMESTAMP(6)` | 是 | 接收及开始执行命令的截止，重试不延期 |
| `version_no` | `BIGINT` | 否 | 默认 0；新任务从 1 递增，对应事件序号 |
| `agent_accepted` | `BOOLEAN` | 否 | 已验证 Agent 持久响应的证据；后续 RETRY_WAIT 不抹掉 |

索引：保留 `idx_tasks_instance_created(instance_id, created_at)`；增加 command_id、idempotency_key 两个唯一索引、node_id 索引、`idx_tasks_created(created_at,id)`。任务列表只读最近 100 条。未添加数据库级级联删除或自动过期删除。

公开 DTO 只返回原任务字段以及 nodeId、agentInstanceId、commandId、executionMode、requestedBy、updatedAt、attempts、resultCode；幂等键、内部地址/Agent 身份、storeId、截止、版本号和接收证据不暴露给浏览器。任务成功不会 UPDATE instances 的状态或指标。

### `task_queue`：可恢复调度

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | 继承 `tasks.id` 实际列类型的主键/外键 | 通常 VARCHAR(64)，一个任务最多一项 |
| `next_run_at` | `TIMESTAMP(6)` 非空 | 下一次可领取时间 |
| `lease_until` | `TIMESTAMP(6)` 可空 | 租约截止，空或过期才可抢占 |
| `lease_owner` | `VARCHAR(36)` 可空 | 每次领取新 UUID，区分同一进程的不同轮次 |

索引 `idx_queue_due(next_run_at,lease_until)`。领取使用带 due/lease 条件的 UPDATE；处理结果先锁队列并确认 owner 与未到期，再锁任务、按版本条件更新、追加事件。网络等待全部在事务外。旧 owner 的迟到结果被忽略；终态和 UNKNOWN 删除队列，保留任务及事件。

### `instance_task_locks`：实例未决任务互斥

instance_id 是主键和 instances 外键，task_id 是唯一非空的 tasks 外键；两列分别继承各自父键的类型、字符集和排序规则，不能假设父表采用同一默认值。与任务、队列、初始事件同一事务创建；任一步失败全部回滚。SUCCEEDED/FAILED 才释放；UNKNOWN 保留，防止用户把不确定重启当失败再做一次。人工核对和解锁尚无接口，不应手工删锁来绕过未知结果。

### `task_events`：只追加状态审计

id 为 UUID 主键，task_id 为 tasks 外键并继承其实际父键定义；event_sequence 为递增 BIGINT，`(task_id,event_sequence)` 唯一。from_status 可空，to_status、actor、reason、occurred_at 非空，时间为 TIMESTAMP(6)。创建事件序号 1、from_status=NULL；后续状态或投递次数变化与任务更新同事务追加，actor 由服务端 operator/worker 决定，不接收浏览器自报。

### `logs`：日志摘要

| 列 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | `VARCHAR(64)` | 否 | 主键 |
| `instance_id` | `VARCHAR(64)` | 否 | `instances.id` 外键 |
| `log_timestamp` | `TIMESTAMP` | 否 | 日志发生时间 |
| `level` | `VARCHAR(16)` | 否 | INFO/WARN/ERROR 等 |
| `message` | `VARCHAR(4000)` | 否 | 清洗后的摘要内容 |

索引：`idx_logs_instance_timestamp(instance_id, log_timestamp)`，用于按实例倒序读取日志。

## 3. 迁移和备份要求

- V4 回填 `agent_instance_id=id`，不改中央 ID、任务或日志外键。历史上已被同名实例覆盖的数据无法凭迁移恢复；重新采集只能重新发现当前实例，不能推断旧任务归属。
- V5 保留所有旧任务 ID/状态/外键，回填身份、更新时间并标记 LEGACY_MOCK；commandId/幂等键为空，投递队列/互斥/事件均不为旧任务生成。旧“成功”仅表示历史数据库模拟，不代表 Agent 或 Docker 执行。
- V4/V5 使用 Java 迁移，继承的 Flyway checksum 为 NULL；发布后仍禁止修改，下个结构变更新增 V6。不要把无 checksum 误解为可以重写历史迁移。
- MySQL DDL 会隐式提交，V4/V5 不能承诺失败后整批回滚。生产迁移前备份并验证恢复；若中断，应依据备份和实际结构恢复后处理 Flyway 状态，不能直接盲目重跑或 repair。

- 已发布迁移不得修改；新结构追加版本 SQL 或 Java 迁移，并测试含历史业务数据的升级。
- 生产迁移前备份 MySQL，并在部署记录中保存 Flyway 版本。
- 数据库不保存密码、私钥、模型 API Key；这些信息只放在运行时密钥系统。
- 原始高容量日志和指标不写入 `logs` 表，后续使用 Loki/Prometheus，MySQL 只保留摘要、索引和审计信息。

### 2026-10-09：V5 上线前的外键排序规则兼容修正

真实 V3 备份在隔离 MySQL 恢复演练中发现：旧 `tasks.id` / `instances.id` 使用 `utf8mb4_unicode_ci`，新 schema 默认是 `utf8mb4_0900_ai_ci`。原 V5 新表继承新默认，创建 task_queue 外键时报 MySQL 3780；此前父子表都来自同一空库默认的测试没有覆盖这一情况。

V5 在执行 DDL 前读取两个父列的实际字符类型、长度、字符集和排序规则，分别为 task_queue、instance_task_locks、task_events 的四个外键列显式声明；不会修改原 ID、父列或历史外键。H2 保持原建表语义。不能只给新表统一指定一个排序规则，因为两个父键本身也可能不同。

这是 V5 首次生产上线前的兼容修正：V5 曾提交 Git 并用于开发测试库，但当时生产仍是 V3，未执行此版本，因此在预发布 V5 内修复阻断点。不能机械追加 V6，因为失败的 V5 无法走到 V6。此例不改变“已正式发布迁移不得重写”的规则。V5 的 Java checksum 仍为 NULL；已经成功应用旧 V5 的库会保留 version=5，校验后 migrate 为 0，不会重新执行本次 DDL，也不应删除历史或强制重跑。

失败演练库保持原状用于复查。MySQL DDL 不原子，已部分失败的 V5 不能直接盲目 repair/重试；本轮从原备份恢复到另一新隔离库重新演练，生产发布仍以备份恢复和整链路检查通过为前提。
