# Argus 控制中心后端开发文档

## 1. 项目定位

`backend` 是 Argus 控制中心的 Java 17 / Spring Boot 3.3.5 服务，负责节点与实例监控、只读日志、可靠任务接收、投递和结果审计。远端执行由独立 Agent 完成，中央不执行 Docker 或 shell。

当前版本是可运行的 MVP：数据通过 `JdbcTemplate` 持久化，Flyway 执行数据库迁移，Agent 快照由定时同步服务写入实例表。生产控制中心先以只读模式运行；Redis、RabbitMQ、Prometheus、Loki 和 AI/RAG 属于后续迭代，不应在当前代码中假设已经可用。

## 2. 分层和调用流程

```text
HTTP 请求
  -> Controller（路径、请求体、参数校验）
  -> Service（业务规则、状态转换、事务）
  -> Repository（参数化 SQL、对象映射）
  -> MySQL / H2
```

一次实例操作的流程如下：

1. 查看令牌只读，独立操作令牌才能写入；全局只读开启时仍禁止写入。浏览器读取 `/api/control/capabilities`，确认目标和 MOCK/DOCKER 模式。
2. `InstanceController` 接收动作、预期模式和 UUID `Idempotency-Key`；`TaskService` 检查开关、中央实例允许列表，在事务外读取 health 任务协议 1.0，绑定目标地址、Agent 节点 ID、storeId 和执行模式。
3. `TaskQueueStore` 在 READ_COMMITTED 短事务中依次锁父节点/实例，复核映射，同事务写入任务、队列、实例互斥与首个事件。唯一幂等键处理并发重复：相同内容返回原任务，不同内容 409；另一个未决任务占用同实例也返回 409。
4. HTTP 202 只表示持久化接收。数据库保存固定 commandId 和微秒精度 expiresAt，所有重试都从持久行构造同一份七字段请求。内部绑定地址、storeId 和租约不进入公共 Task DTO。
5. `TaskWorker` 使用随机领取标识与条件更新抢占租约；每轮事务外复核身份、地址、模式，再 GET commandId。只有同一 Inbox 的明确 404 才允许 POST 原命令。POST 前持久化投递次数；网络、拒绝或丢响应均先查再决定，不能直接生成新命令。
6. 合法结果与追加事件同事务保存。SUCCEEDED 必须有开始/完成时间且观测状态与动作一致；成功不更改实例监控数据。UNKNOWN 停止自动投递并保留实例互斥，人工核对入口后续单独实现。

`InstanceService.applyAction` 已移除，任务不能再通过更新数据库伪造重启成功。旧记录为 `LEGACY_MOCK`、无 commandId/队列，永不重放；新任务来源为 Agent 的 MOCK 或 DOCKER。生产控制默认关闭，本轮只验证本机 mock，不操作真实游戏容器。用户/项目 RBAC、人工审批、多租户和 UNKNOWN 人工处理尚未实现。

普通进程重启复用数据库队列；旧 worker 过期后不能覆盖新租约持有者。已确认接收的证据单独持久化，后续网络失败不能抹掉它；曾接收过的任务再次 404 必须 UNKNOWN。Agent storeId/地址/目标变化、非法身份、无效成功证据或超过确认期限都保守停止。控制开关关闭后可继续 GET 查询结果；同操作令牌、同幂等键仍可找回已保存任务，但全局只读仍阻止 POST。

任务执行采用单个固定延时 worker，每轮最多处理一条；它和采集使用大小为 2 的调度池，慢任务不会独占采集调度线程。这是有界顺序调度，不是高吞吐队列。每次 HTTP 完整响应有 connect+read 总截止和 64 KiB 上限，超时取消请求及正文订阅；不能仅依赖 JDK 17 的 HttpRequest.timeout。开启控制时租约必须大于三次完整请求预算，关闭控制后的恢复读取自动使用至少覆盖预算的租约。默认命令可接收窗口 5 分钟，另加 5 分钟结果确认宽限；明确缺失且过期才可安全 FAILED，无法确认则 UNKNOWN。

只读网关接口为：

- `GET /api/agent-gateway/nodes/{nodeId}/health`
- `GET /api/agent-gateway/nodes/{nodeId}/instances`
- `GET /api/agent-gateway/nodes/{nodeId}/instances/{instanceId}/logs?limit=100`
- `GET /api/instances/{id}/logs?limit=100`（中央 ID 自动定位来源节点，推荐前端使用）

`AgentSnapshotSyncService` 以固定延迟 60 秒顺序读取节点 health/instances；它使用只读 GET，生产只读拦截器不会阻止内部快照持久化。每次尝试更新 `lastCheckedAt`，健康有效时才更新 `lastHeartbeat`，完整清单校验和数据库事务成功后才更新 `lastSuccessfulSyncAt`。健康成功但清单失败标记 PARTIAL；健康失败标记 FAILED/OFFLINE。固定错误码替代远端原文。

`AgentSnapshotParser` 先验证整份数组，拒绝非数组、重复局部 ID、坏行和错误类型。`AgentSnapshotStore` 在 READ_COMMITTED 事务中整批保存实例与节点成功时间；任何数据库失败回滚整批。空数组是有效的完整发现结果，历史实例不会删除或刷新。每个被看到实例的 `lastSeenAt` 与节点成功批次时间相等，未出现实例保留旧时间，前端可立即标记旧快照。

多节点身份以 `(nodeId, agentInstanceId)` 查询和去重，中央 `id` 关联任务、日志、详情链接。旧记录保持原 ID；新发现生成 UUID。并发首次发现由复合唯一键兜底，冲突后重读获胜者 ID。当前调度仍为单进程顺序读取，没有宣称实现分布式采集调度或高并发吞吐。

采集更新仅作用于仍存在的节点，HTTP 等待期间节点被删除时安静结束，不会重新插入。完整快照事务与节点删除事务都先锁父节点行，再处理实例，避免并发删除后重新出现节点或残留实例；网络等待阶段不持有数据库行锁。

### 采集协议 1.1

健康响应增加 `protocolVersion=1.1`；健康来源为 HOST（本地演示记录可为 MOCK），实例来源为 DOCKER 或 MOCK。每份指标带 `dataSource`、ISO `sampledAt`、`metricsStatus`。主机可用性看 CPU/已用内存/总内存三项；实例可用性只看 CPU/内存两项，尚未支持的玩家数为 NULL，不影响资源指标 AVAILABLE。全有值为 AVAILABLE、部分有值为 PARTIAL、全 NULL 为 UNAVAILABLE；零值可以是真实采样，不能作为失败占位符。

`sampledAt` 是 Agent 采样尝试时间，单独存在不证明指标可用或仍新鲜。请求失败保留上次成功值和时间；合法的不可用响应保存 NULL/UNAVAILABLE。MOCK 永远标为演示；初次无元数据的旧 Agent 只同步身份和状态，指标为 LEGACY/UNKNOWN，无可信采样时间。已有记录改由旧 Agent 响应时，保留旧数值与采样时间，但降为 LEGACY/UNKNOWN，不能使用更新后的 `lastSeenAt` 冒充新实测。未知协议版本或不完整元数据按无效响应处理。

网关默认关闭（`ARGUS_AGENT_GATEWAY_ENABLED=false`），开启时必须设置 `ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS`，并保持 `ARGUS_AGENT_GATEWAY_READ_ONLY=true`。网关只允许 `http/https`，禁止重定向，不提供通用 URL 代理，也不会把远端错误正文透传给浏览器。Agent 令牌使用 `ARGUS_AGENT_AUTH_TOKEN` 注入，不写入节点表或文档。

本地联调示例：节点表中的 `address` 填 `127.0.0.1:8090`，然后设置：

```powershell
$env:ARGUS_AGENT_GATEWAY_ENABLED = "true"
$env:ARGUS_AGENT_GATEWAY_ALLOWED_HOSTS = "127.0.0.1"
```

## 3. 启动和配置

### 本地 H2

```bash
mvn spring-boot:run
```

默认使用 `./data/argus` 文件库，Flyway 自动执行 V1–V5。本地演示数据开关默认为 true，预置节点和实例显式标记 `dataSource=MOCK`；迁移旧采集数据始终标为 LEGACY，不能当成演示或实测重新命名。V5 历史任务另标 LEGACY_MOCK，不生成队列。

### MySQL

```bash
$env:SPRING_PROFILES_ACTIVE = "mysql"
$env:MYSQL_HOST = "数据库地址"
$env:MYSQL_DATABASE = "argus"
$env:MYSQL_USER = "argus"
$env:MYSQL_PASSWORD = "运行时注入的密码"
java -jar target/argus-control-center-0.1.0-SNAPSHOT.jar
```

`mysql` profile 的演示数据开关默认为 false。密码只通过环境变量或部署平台密钥注入，不写入仓库、文档或前端代码。

### 跨域

`ARGUS_CORS_ORIGINS` 是逗号分隔的允许来源，例如 `https://ops.example.com,http://localhost:5173`。默认只允许本地 Vue 开发地址，避免生产环境使用 `*`。

生产安全开关：`ARGUS_API_READ_ONLY=true` 时，具备操作权限的写请求仍返回 405；普通查看令牌的写请求会先被角色检查拒绝为 403。浏览器预检 OPTIONS 不需要令牌，CORS 允许 `Authorization` 与 `Idempotency-Key`。

域名准备解封前可设置 `ARGUS_API_AUTH_REQUIRED=true` 和运行时注入的
`ARGUS_API_ACCESS_TOKEN`，此时除 `/api/health` 外的控制中心 API 必须携带
`Authorization: Bearer <token>`；令牌缺失时应用启动失败，错误令牌返回 401。
独立的 `ARGUS_API_CONTROL_TOKEN` 具有读写角色，查看令牌不能写节点、心跳、删除或创建任务。操作身份固定记为服务端 `operator`，不接受客户端自报。任务事件已有持久审计，但这两个令牌角色尚未替代用户登录、项目 RBAC 和令牌轮换。

可靠控制只有在以下配置同时成立时开启：`ARGUS_TASK_CONTROL_ENABLED=true`、API 鉴权开启且查看/操作令牌非空不同、读取网关启用并保持 read-only=true、`ARGUS_AGENT_GATEWAY_ALLOW_CONTROL=true`、强制非空主机白名单、非空且不同的 Agent 读取/控制令牌。中央实例允许列表为空则没有可执行目标；真实模式还要求 `ARGUS_TASK_ALLOW_DOCKER=true`。旧网关的 read-only 只描述原 GET 代理，不能通过它绕过额外控制 gate。默认全部控制关闭。

IDEA 仅在个人运行配置中填写真实值，不保存为项目共享文件。Agent 控制令牌与查看令牌不写入数据库；节点目标地址只保存在运行数据库及内部任务绑定中，不进入公共任务 API。

## 4. 数据库变更流程

1. 在 `src/main/resources/db/migration` 新增 SQL 版本，或在 `src/main/java/db/migration` 新增 Java 版本；下一个版本为 V6。
2. 只追加迁移，不修改已发布 V1–V5。V4/V5 Java 迁移的默认 checksum 为 NULL，也不能修改已发布实现。
3. 在含旧节点、实例、任务、日志的 H2 与隔离 MySQL 库上执行 Flyway V3→V4 与 V4→V5。前者验证旧 ID、外键、复合唯一键、NULL、时间精度与发现并发；后者验证旧任务为 LEGACY_MOCK 且没有投递，以及新队列租约/互斥/事件，不以空库建表代替旧库迁移。
4. 部署前备份数据库并记录迁移版本；生产库禁止通过应用启动自动插入演示数据。

MySQL DDL 隐式提交，V4/V5 结构迁移不具备整批失败回滚保证；这里的“整批事务”指运行时快照或任务 DML。迁移中断需要备份恢复与人工核对结构，不能盲目 repair 后重跑。历史同名覆盖已丢失的归属无法由 V4 恢复。

## 5. 代码规范

- Controller 只负责 HTTP 适配，不拼接 SQL、不读取密钥、不执行系统命令。
- Service 负责领域校验和状态机；跨多次写入使用 `@Transactional` 或显式 `TransactionTemplate`。任务采用后者，所有 HTTP 必须在事务外。
- Repository 只使用参数化 SQL，查询结果必须显式映射字段。
- 新增公开接口、领域字段或数据库列时，同步更新 `变量与接口文档.md` 和 `数据库表文档.md`。
- 注释解释业务原因和边界，不重复翻译显而易见的 Java 语法。
- 错误消息不返回密码、访问令牌、私钥或完整远程日志。

## 6. 本地验证

```bash
mvn test
mvn clean package
```

测试覆盖应用/认证、两个本机 HTTP Agent 的同名实例与日志隔离、失败及无效整批响应、空数组、数据库失败事务回滚、NULL/零值/MOCK/LEGACY、含历史记录的 H2 V3→V4 迁移和并发首次发现。另有 4 项真实线程与本机 HTTP 并发回归：在 health 或 instances 网络等待期间删除节点，分别让迟到响应成功或返回 503，验证节点与实例均不会复活。

`MigrationCompatibilityTest#upgradesExplicitIsolatedMysql` 默认跳过，仅在显式设置 `ARGUS_TEST_MYSQL_URL`、`ARGUS_TEST_MYSQL_USER`、`ARGUS_TEST_MYSQL_PASSWORD` 时执行。测试要求 URL 为 `jdbc:mysql://127.0.0.1:<端口>/argus_test_<名称>` 或 `argus_refactor_<名称>`，库内必须为空；它不会读取生产 `MYSQL_*` 配置，也不会自动清空已有库。凭据只从私有运行环境传入。该用例执行真正的 Flyway 旧库升级、外键验证、大小写敏感身份和并发冲突测试。

`TaskMigrationCompatibilityTest#upgradesExplicitEmptyIsolatedMysqlV4` 使用独立的 `ARGUS_TEST_TASK_MYSQL_URL/USER/PASSWORD`，只接受回环地址和 `argus_refactor_tasks_*` 新空库。它以真正 Flyway 升级 V4→V5，检查 LEGACY_MOCK、零历史队列、外键保留、持久绑定微秒精度、互斥、同键返回、双线程抢占仅一 owner、完成后的迟到写入拒绝、事件与重开读取。没有读取生产 `MYSQL_*` 配置或清空旧库。
