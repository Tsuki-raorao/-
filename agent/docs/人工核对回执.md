# Agent 人工核对回执

这项功能只记录 `ACKNOWLEDGE_UNCERTAINTY`：人工核对后接受原结果仍然不确定，允许未来独立的新操作。它没有“重试原动作”“强制成功”或“忽略 storeId”入口。原 `.task`、UNKNOWN 状态、结果码、时间、原观测保持不变。中央协议以 [共享契约](../../docs/UNKNOWN任务人工核对设计.md) 为准。

## 独立授权

`review.enabled` / `ARGUS_AGENT_REVIEW_ENABLED` 默认 false；`review.instances` / `ARGUS_AGENT_REVIEW_INSTANCES` 默认空。显式开启时要求非空且不同的读取令牌、控制令牌和精确局部实例名单。与 `control.enabled` 独立：可以停止动作投递后核对旧任务，但核对不会间接开放 start/stop/restart。中央全局只读优先拒绝核对写入；Agent 不负责推断中央全局设置。

所有任务、确认前证据及回执接口都要求独立控制 Bearer；查看令牌无权调用。GET 旧结果不依赖 review 开关。所有 POST（包括重复请求）先检查当前 review 开关、关闭状态、健康 Inbox 和名单；首次回执还必须通过绑定和执行资源门槛。重复 POST 只返回已有回执，不重新检查旧互斥或执行观察。

## 接口

| 方法 | 路径 | 结果 |
|---|---|---|
| GET | `/api/agent/tasks/{commandId}/review-evidence` | 原 TaskView、checkedAt、当前授权事实、锁归属及执行资源状态；不调用 Docker |
| POST | `/api/agent/tasks/{commandId}/resolutions` | 首次完整持久回执 201，相同固定请求 200 |
| GET | `/api/agent/tasks/{commandId}/resolutions/{resolutionId}` | 原回执 200，不存在 404 |

POST 的十二字段是 `resolutionId/instanceId/action/expectedNodeId/expectedStoreId/expectedExecutionMode/expectedCommandExpiresAt/decision/reason/evidenceDigest/acknowledgeNoReplay/acknowledgeResidualRisk`。仅末两项允许真正 JSON boolean 且必须 true，其余严格字符串；重复/未知键、嵌套、数字、尾部内容、缺字段均拒绝。reason 非空，最多 500 个 Unicode 码点；NUL 和未配对代理字符拒绝。Agent 验证中央标准文本已按 ECMAScript String.trim 空白集合裁剪首尾且 CR/CRLF 已换为 LF，拒绝未标准化请求，不静默改写哈希正文。NBSP、FEFF、全角空格属于该集合；U+001C 不属于，原样保留。证据只接收 SHA-256 摘要，不读文件、附件或远程 URL。

原 expiresAt 仅作不可变身份比对，即使已经过期也允许核对；核对请求没有额外 TTL。此授权不产生动作，未来新动作仍需独立确认、新 UUID 和新的执行期限。

requestHash 为共享协议的十四个固定字段：每项 UTF-8 编码，先写四字节大端字节数再写正文，整体 SHA-256 小写 hex。包括协议域 `argus-resolution-v1`、路径 commandId、其余身份/理由/证据以及两个 `true` 字符串。Agent 自己计算，不信任客户端自报哈希；中文、换行和 emoji 使用字节长度，不能按字符数或 JSON 文本哈希。

确认前证据 `knownProcessesActive` 聚合已知子进程、输出 reader 存活或清理未确认。`workerActive` 包括原任务 scheduled、执行作用域和正在核对的观察作用域。`lockDisposition` 为 `OWNED_BY_COMMAND/NONE/OWNED_BY_OTHER`。它们是事实快照，提交时还会重新检查，不能当作永久授权。

## 核对与互斥

首次请求逐项比较持久原命令的 node/store/mode/局部实例/动作/原期限和当前 Agent 身份。只允许 UNKNOWN、SUCCEEDED、FAILED；PENDING/RUNNING 或当前执行资源未退出拒绝。UNKNOWN 的未决锁必须属于原 command；原任务已是终态时允许没有锁，但不允许占用别的 command 的锁。

对同一 command 的核对串行处理，慢观察在全局任务监视器之外执行，原互斥仍保留。目标别名指向另一容器则拒绝。当前观察只记录 RUNNING/STOPPED/UNKNOWN；失败记录 UNAVAILABLE 和 null，不回显错误正文。观察结束再检查开关、绑定、任务、原锁及已知进程/reader；观察自身留下资源也不能放行。

先原子同步 CLOSED 回执，再 `remove(instanceId, commandId)` 条件释放原锁。重复请求只返回原回执，不重新观察、更新时间或删除锁；即使后续新任务已占锁，旧命令重试仍只返回原 UNKNOWN，旧核对不会影响新锁。原 TaskView 终态补偿使用 `CONFIRMED_TERMINAL`，不改历史任务；UNKNOWN 使用 `ACKNOWLEDGED_UNKNOWN`。

## 持久格式及恢复

`<commandId>.resolution` 与原任务位于同一独占 Inbox，每条原任务最多一条回执。格式是四字节魔数 `0x41525231`、四字节 JSON 长度、UTF-8 JSON、32 字节 SHA-256。JSON 保存固定 request 字符串、requestHash、原 TaskView 字符串、创建时间、分类、进程评估和独立观察。校验和发现损坏，不是管理员防篡改签名。

同目录临时文件写完整并 force，再 ATOMIC_MOVE，支持的平台再目录 force；不支持原子移动时拒绝，不能退化为直接覆盖。先同步后更新内存，写失败停用新写入并保留原锁。Inbox 已满仍可为原任务存一条回执，但不能清理原 `.task` 回收去重容量。

启动先加载原任务，再严格校验回执：对应原任务必须存在，TaskView 完整相等，绑定/requestHash/文件名/resolutionId 唯一约束成立。损坏、孤儿回执、丢 store.id 都拒绝启动。有效 CLOSED 回执使旧 UNKNOWN 不再重建锁；原命令记录永不删除，迟到 POST 不重放。

## 进程与外部副作用边界

`ExecutionRegistry` 仅登记当前 command 作用域启动的 Process、已捕获后代及 reader。runner 超时/输出超限先尝试清理，随后实际检查存活状态；限时等候结束不等于已退出，未确认时抛 `CLEANUP_UNCONFIRMED` 并保留登记，任务不能被当作已知成功。旧 helper 或 reader 仍活时，核对返回 409 `review_executor_active`。

`CURRENT_PROCESS_CLEARED` 只证明当前 JVM 已知执行资源清理；新 JVM 载入历史任务只能报告 `PRIOR_PROCESS_UNVERIFIED`。当前核对观察的进程使用独立作用域，不会把历史未知的清理评估升级为已确认。进程树快速脱离、JVM 强制退出、旧孤儿与 Docker daemon 在 CLI 退出后继续动作都不受本登记表完全证明。因此两项人工确认必须明确承认：不重放原命令、接纳残留副作用风险。当前 RUNNING/STOPPED 不能证明原动作成功。

更换 Inbox/store/node/mode 或原记录缺失时拒绝首次核对，没有跨身份强制解锁。恢复旧备份的反回滚、Windows 目录 fsync、磁盘断电一致性边界与原 Inbox 相同；不能以本模块测试宣称已解决。

## 验证范围

新增 5 项资源登记测试和 36 项核对测试，连同原 48 项共 89 项。覆盖真实 Java helper/reader 存活、UNKNOWN 与 active scope、观察资源残留、提交前临时文件崩溃/回执提交后进程 halt、启动重建锁、原文件字节不变、并发去重、旧回执不解新锁、满容量核对、损坏/坏哈希/孤儿/store 丢失、两个独立开关、控制令牌、严格 ACK 类型和回执时间矛盾。要求 `task.finishedAt <= observedAt <= createdAt`，原任务未来结束时间或早于任务结束的核对观察都拒绝。脚本另用 PowerShell JSON 解析器检查回执与确认前证据。增量未访问生产或操作真实 Docker。
